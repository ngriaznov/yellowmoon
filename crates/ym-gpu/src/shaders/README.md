WGSL compute shaders live in this folder. Each kernel has a CPU reference (`src/cpu/` for the raw stages, `ym_color::display::ColorChain` for the colour chain) and a parity test with a stated maximum absolute error.

| File | Kernel | CPU reference |
|---|---|---|
| `common.wgsl` | helpers shared by every kernel: LogC3/LogC4, sRGB and BT.1886 transfer, mirror index, NaN test by bits | `ym_color::{logc, encode}` |
| `spike_normalize.wgsl` | R1 normalise + R4 gains | `cpu::normalize`, `cpu::gains` |
| `spike_demosaic.wgsl` | R6 bilinear demosaic | `cpu::demosaic::bilinear` |
| `spike_matrix.wgsl` | fixed 3x3 and sRGB (the M0-07 spike's last pass) | `kernels::spike::cpu_reference` |
| `color.wgsl` | C1 to C13 in one pass: fused matrix, C7, C8, C9, C10 (CDL, tetrahedral LUT, LogC3 path, blend), C11 curves, C12 dispatch, C13 encode and dither | `ym_color::display::ColorChain` |
| `aces2.wgsl` | the ACES 2 output transform, with tables uploaded from `ym_color::aces2` | `ym_color::aces2` |
| `log_guided.wgsl` | RA-09 log-guided fast demosaic, all-float form: four dispatches of one entry point (log and horizontal guide filter; vertical filter and `exp2`; structure measures with the horizontal 5-sum; vertical 5-sum and reconstruction). Scratch planes are always f32; only the mosaic and the output planes use the storage mode. `tests/gpu_log_guided.rs`: max abs error 3.1e-6 on the vectors, 5e-6 on random frames, 3.2e-6 on 2048 x 1365 | `cpu::demosaic::log_guided::demosaic_float` |
| `output_sharpen.wgsl` | RA-09 output sharpening: plain functions for eight passes (luma, difference-form high-pass rows and columns, gain-map terms, separable blur, accumulation, 5 x 5 halo-limiter window, limiter clamp and ratio transfer); `kernels/output_sharpen.rs` appends one `main` per pass, so each pass is its own pipeline with its own auto-generated layout. **All planes are f32 in every storage mode** (no `ST_ELEM`, no accessors: the limiter compares luma values exactly) and sums accumulate in f32, where the CPU uses f64 | `cpu::output_sharpen` |
| `diffraction.wgsl` | RA-09 R8 diffraction deconvolution: plain functions for nine passes (luma with inverse noise variance and clip penalty; 5 x 5 envelopes; layers; Gaussian rows and columns for `Y` and for `Z`; PSF convolutions and residual; moment row sums; vertical sums and the 3 x 3 solve; coefficient smoothing, correction and ratio transfer), one pipeline per pass like `output_sharpen.wgsl`. The PSF kernel, the Gaussian taps and the noise constants come from the CPU planner. **All planes are f32 in every storage mode**; sums and the Cramer solve are f32 where the CPU uses f64. The luma is an exact expansion (Dekker and Knuth in f32, hidden from the optimiser with an xor against a runtime zero) because the envelope counts compare neighbouring lumas; `fma` is not used (lavapipe lowers it unfused). `tests/gpu_diffraction.rs`: max abs error 8.9e-7 on the 13 image vectors, 5.1e-6 on random frames, 4.8e-7 on 2048 x 1365 through 512 px tiles, tiles bit-identical to the whole frame | `cpu::sharpen::diffraction` |

The files are templates: `ST_ELEM` and the `//@ACCESSORS name [ro]` lines are expanded by `kernels/shader.rs` for the device's storage mode (native f16, packed f16, f32), and the constants (LogC, gamut matrices, grade constants, table offsets, the geometry of the ACES 2 hue tables) are written in front of the module from `ym_color`, so those numbers are not typed twice. The ACES 2 algorithm's own constants (the 27.13 of the cone response, the smoothing and blend factors, the chroma-compression polynomial) are private to `ym_color::aces2` and stay in `aces2.wgsl` beside the code that uses them; the OpenColorIO vectors and the CPU parity tests pin them. `kernels::shader_source(mode, id)` returns the final text; `tests/shaders_naga.rs` validates it offline.

Conventions: one thread handles two horizontally adjacent pixels (a packed f16 word is written by one thread), `@workgroup_size(16, 16)`, row strides are even, planes are planar. Look cubes, shapers and curve tables are f32 storage buffers read with explicit tetrahedral and linear interpolation, never hardware filtering (`docs/02`, C10 and C11).
