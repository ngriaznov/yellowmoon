# Grading photos through the Claude Code CLI and Google's Antigravity CLI (`agy`): commands, privacy, process handling, design

Research date 2026-10-26. Scope: the owner wants Auto (`docs/19-apple-auto.md`) to be able to use the person's own installed `claude` (Claude Code) and `agy` (Google's "AGY CLI") instead of, or next to, Apple Intelligence: a new dropdown in Preferences, hidden (with the prompt field) when no provider is available, and cross-platform process handling. The owner's decision of 2026-10-26 on rule 7: "Ym won't access network, we will invoke agy and Claude - they will access network." Section 5 is written from that reading.

Method. Official documentation was read (Claude Code docs at `code.claude.com`, Anthropic's vision docs, Google's Antigravity docs and ToS, the `antigravity-cli` README and CHANGELOG, the Google Developers Blog post on the Gemini CLI transition, the Rust blog post on CVE-2024-24576, crates.io metadata, docs.rs source of `which`). Then, in a scratch folder and never in the repository: Claude Code 2.1.310 was installed with `npm install` (the native binary the npm package carries) and its `--help` read; the `agy` 1.4.7 tarball was downloaded from the URL in Google's own install manifest, its SHA-512 checked against the manifest, and only `agy --version` and `agy --help` were run, in a network namespace with no network and an empty home. A further attempt to run `agy -p` offline was refused by the session's permission classifier and was not repeated, so everything about `agy` beyond `--help` is from documentation and the CHANGELOG, or read from the binary's strings, and is marked. No account was signed in, no API key and no real credential was used, and no image went to any service.

Claude Code was also exercised against a **local mock of the Anthropic Messages API** (a 150-line Node server on `127.0.0.1`, a dummy token, run inside a network namespace with only loopback and a DNS stub that logged every name asked). That shows, byte for byte, what `claude -p` puts in a request and which hosts it tries to reach, without any service seeing anything. The picture used was a synthetic orange-to-navy gradient. Marks used below: **[run]** observed that way, **[doc]** from the cited source, **(unverified)** not checked, listed again in section 7.

## 0. Short answer

1. **"AGY" is Google's Antigravity CLI: the command `agy`, v1.4.7 today** (section 1). It is a closed-source Go binary (no `LICENSE` in its repository), installed by a `curl | bash` or PowerShell script to `~/.local/bin/agy` or `%LOCALAPPDATA%\agy\bin\agy.exe`, signed in with a Google account (system keyring) or `GEMINI_API_KEY`. It replaced Gemini CLI (`gemini`) for consumers on 2026-06-18. It has a print mode (`-p`) with `--output-format json` and `--json-schema`.
2. **Claude Code can take the picture in the request itself, with no tools and no file access.** `claude -p --input-format stream-json --output-format stream-json` accepts a user message with a base64 `image` block; with `--tools ""` and `--json-schema` the only tool the model sees is `StructuredOutput`; the run is one API request **[run]**. This is the cleanest route of the two by a wide margin.
3. **`agy` cannot take an image on stdin.** Its stream-json input accepts text blocks only (a different block type ends the session with an error) **[doc]**, and its print mode has no image flag. The only route is a file path in the prompt, which the agent opens with its `view_file` tool in an empty workspace folder. That runs the full agent harness (about 10 k input tokens per call in Google's own sample) and obeys the person's own tool permissions, so it is slower, less predictable and carries prompt-injection risk (section 3.7).
4. **Structured output.** Both CLIs have `--json-schema` and return the parsed object in `structured_output` of a JSON result. Neither guarantees it: Claude Code retries once with a reminder and then returns a plain-text success without the field **[run]**; `agy` documents the field "present only with `--json-schema`". The Rust side must check the field is present and validate it against our own schema (`jsonschema` is already a dependency of `ym-core`).
5. **Availability without a request.** Claude: `claude --version` (20 ms) and `claude auth status` (JSON, exit 0 when signed in, 1 when not) **[run]**. `agy`: `agy --version`; there is no `auth status` subcommand, so the sign-in check is `agy -p /usage --output-format json`, which the CHANGELOG says answers "without starting an agent turn, spending quota" (1.1.11), and which fails with "authentication required" when signed out (the string is in the binary) **(unverified: not run)**.
6. **Determinism: none is available.** Neither CLI exposes temperature or seed (`--help` of both; the Claude request body has no `temperature` key **[run]**). Answers are not reproducible. Section 5 says how to report that (as `docs/19` §7 does for Apple) and why the pinned `ym:Settings` still make an exported picture reproducible from its own metadata.
7. **Privacy.** Claude Code's own telemetry is switched off by one environment variable, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`: with it the CLI made exactly one connection (the request); without it, it also looked up `api.anthropic.com` and `http-intake.logs.us5.datadoghq.com` (to reach them) and wrote about 170 KB of usage events per run to `~/.claude/telemetry` **[run]**. For `agy` there is no documented switch: telemetry ("Interactions") is an account setting in `/config`, and Google's terms say Google staff may review Interactions unless the person opts out **[doc]**.
8. **Terms.** Anthropic: an end user signing in to the *unmodified* binary with their own plan is expressly not prevented; developers must not "route requests through" plan credentials, collect credentials or intermediate sign-in **[doc]**. So Yellowmoon must only spawn the person's own `claude`, never read, pass or store credentials. Google: the Antigravity terms call "using third party software, tools, or services to access the Service" a breach (the example given is OpenClaw using Antigravity OAuth), which may or may not cover spawning the first-party binary. This is the one item that needs the owner's judgement (section 7, question 1).
9. **Cross-platform spawn recipe** (section 4): resolve the executable with `which` (PATHEXT on Windows) *and* known install folders, because both installers put the binary in `~/.local/bin`, which the Finder-launched macOS app does not have on its PATH; never go through `cmd /C` or a `.cmd` shim (resolve the real `claude.exe`); put the picture on stdin, never in an argument; run in an empty temp folder; kill the whole process group (Unix) or job object (Windows) on timeout or cancel. All crates needed are MIT or Apache-2.0 (`which`, `process-wrap`, `tempfile`; `jsonschema` and `tempfile` are already in `Cargo.lock`).
10. **Recommended shape** (section 6): one new crate (`ym-agents`) with two `AutoAdvisor` implementations behind the trait `docs/19` §12 already defines; a provider dropdown that lists only what is found; per-provider consent, default off; the same answer form as Apple, sent as a JSON Schema.

If the owner ever wants a third provider, Gemini CLI could take the picture with an `@file` mention in `-p` mode (its `--help` shows `-p`, `-o json`, `--skip-trust`, no image flag) but it is a poor target now: consumer sign-in ended, only API-key and enterprise users remain.

## 2. Claude Code (`claude`)

Version tested: **2.1.310** (npm `latest`; `stable` is 2.1.308). The package `@anthropic-ai/claude-code` is a thin wrapper: its `bin` entry is a native binary (`bin/claude.exe`, even on Linux and macOS) delivered through per-platform optional packages; "The installed `claude` binary does not itself invoke Node" [doc, setup page; run]. The licence is "All rights reserved. Use is subject to the Legal Agreements" [run, `LICENSE.md`]: we never ship or link it, we spawn the person's copy.

### 2.1 One-shot call with no state, no tools, no prompts

```text
claude -p
  --input-format stream-json --output-format stream-json --verbose
  --safe-mode --tools "" --no-session-persistence --max-turns 3
  --model sonnet --effort low
  --system-prompt-file <tmp>/instructions.txt
  --json-schema '<JSON Schema, one line>'
  --disable-slash-commands --strict-mcp-config
```

with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` in the environment, the working directory an empty new temp folder, and one line on stdin (section 2.2). Each flag, and why:

| Flag | What it does | Evidence |
|---|---|---|
| `-p` | print mode, no TUI, no workspace-trust dialog ("skipped when Claude is run in non-interactive mode") | help text [run] |
| `--input-format stream-json` | the only way to send an image in print mode; **requires** `--output-format stream-json` (`Error: --input-format=stream-json requires output-format=stream-json.`, exit 1) | [run] |
| `--output-format stream-json --verbose` | NDJSON events; the **last line** is the `result` object | [doc] headless page; [run] |
| `--safe-mode` (since 2.1.169) | "all customizations disabled" (CLAUDE.md, plugins, skills, hooks, MCP servers, agents); "Auth, model selection, built-in tools and permissions work normally". **Without it a plain `claude -p` ran the person's `UserPromptSubmit` and `SessionStart` hooks from `~/.claude/settings.json`**; with it they did not run, while `model`, `env` and `apiKeyHelper` from the same file were still honoured | [run] (three configurations, below) |
| `--tools ""` | no built-in tools: the request's tool list was `["StructuredOutput"]` plus a placeholder `DeferredToolPlaceholder` | [run] |
| `--no-session-persistence` | print mode only: no transcript under `~/.claude/projects`; none was written | [doc] CLI reference; [run] (no `.jsonl` created) |
| `--max-turns 3` | with `--json-schema` the run reports `num_turns: 2` after one API request; `--max-turns 1` also succeeded in the mock; 3 leaves room for the one retry of 2.3 | [run] |
| `--model sonnet` | **always pass a model**: the default on the Anthropic API and every claude.ai plan is Opus 5.5 [doc, model page]. Aliases move (`sonnet` is Sonnet 5.5 on the Anthropic API today); the id that answered is the key of `modelUsage` in the result (`claude-sonnet-5-5`) and is what to record | [doc]; [run] |
| `--effort low` | `low`/`medium`/`high`/`xhigh`/`max`; Sonnet 5.5 defaults to `medium`. Thinking is always adaptive on Sonnet 5 and later and cannot be switched off [doc, env-vars page: `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING` "has no effect on … Sonnet 5 and later"]; `low` cuts it | [run] (`output_config.effort: "low"` in the request) |
| `--system-prompt-file` | replaces Claude Code's system prompt with the file's text. The request still starts with the identity line "You are a Claude agent, built on Anthropic's Claude Agent SDK." and then our text verbatim. It is hidden from `--help` in 2.1.310 but documented in the CLI reference and accepted. `--system-prompt "<text>"` does the same; **a file avoids the Windows `.cmd` quoting problem and any length limit** | [run] |
| `--json-schema '<schema>'` | inline JSON only (a string); see 2.3 | [run] |
| `--disable-slash-commands`, `--strict-mcp-config` | belt and braces on top of `--safe-mode` | help text |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | "auto-updates, telemetry, error reporting, the `/feedback` command, … release notes, … availability checks … feature-flag fetching" [doc]. Observed effect in 2.7 | [run] |

**Do not use `--bare`.** It is the documented "recommended mode for scripted and SDK calls", but "Anthropic auth is strictly `ANTHROPIC_API_KEY` or `apiKeyHelper` via `--settings` (OAuth and keychain are never read)" [run, help text; doc]. A person signed in with a Claude subscription, which is most people, would be signed out.

**Settings isolation test [run].** A scratch home with `~/.claude/settings.json` holding `{"model":"opus","apiKeyHelper":"echo …","env":{"ANTHROPIC_DEFAULT_OPUS_MODEL":"claude-mock-from-settings"}}` plus a `UserPromptSubmit` and a `SessionStart` hook that `touch` a marker file. Plain `-p`: model, key helper and env honoured, both hooks ran. `--safe-mode`: model, key helper and env honoured, **no hook ran**. `--setting-sources project`: nothing from the user file applied (hooks did not run, nor did `env`/`apiKeyHelper`). So `--safe-mode` is the right flag and keeps people on Bedrock/Vertex/gateway settings working; `--setting-sources project` is the fallback for a CLI older than 2.1.169 but drops the person's own provider settings.

**Time limits.** `--max-budget-usd` exists (print mode only) but is a spend cap, not a time limit; the time limit is ours (4). On SIGTERM `claude -p` exits 143 and records nothing [doc].

### 2.2 Passing the image

Three ways exist. The first is the recommendation.

**(a) Base64 image block on stdin, tool-less [run + doc].** One JSON object per line:

```json
{"type":"user","message":{"role":"user","content":[{"type":"image","source":{"type":"base64","media_type":"image/jpeg","data":"<base64>"}},{"type":"text","text":"Grade this photo."}]}}
```

then close stdin. The shape is the Agent SDK's `SDKUserMessage` ([doc], streaming-input page, "Image uploads"). The request that reached the mock carried exactly one `image` block with the JPEG bytes and the text block, `tools: [StructuredOutput]`, and nothing about the file system. Claude "works best when images come before text" [doc, vision page], which is the order above, as in Apple's prompt. If the block's `source` is malformed the CLI sends the model a text note instead of failing (`[Image could not be processed: …]`) [doc]: the Rust side must never rely on an error to notice a bad picture.

**(b) A path in the prompt and the `Read` tool.** `claude -p "Grade the photo at ./photo.jpg" --tools Read --allowedTools Read` with the picture in the working folder. Checked [run]: the model asked for `Read`, the CLI executed it and the second request carried the picture as an `image` block inside a `tool_result`. Costs a second request and puts the temp folder's path and an "# Environment" block (working directory, platform, OS version, date) into the conversation. `--restricted` additionally confines the file tools to the working directories [doc]. Use only as a fallback.

**(c) `@file` mentions.** Documented for the interactive prompt ("Explain the logic in @src/utils/auth.js"); `CLAUDE_CODE_DISABLE_FILE_MENTIONS` exists. Not tested in `-p` and not needed.

**Formats and limits [doc, Anthropic vision page].** JPEG, PNG, GIF, WebP. At most 10 MB per image (base64) on the API, 8000×8000 px, 100 images per request. An image costs `⌈width/28⌉ × ⌈height/28⌉` visual tokens: a 768×512 picture is 28 × 19 = 532 tokens, 768×576 is 588, 768×768 is 784. Long edges above 1568 px (2576 px on models from 4.7) are downscaled, so 768 px is never resized. "Claude does not parse or receive any metadata from images", so EXIF is not read even if present (ours carries none). Piped text stdin is capped at 10 MB [doc]; our message is about 0.3 MB.

**Which format.** A JPEG at 4:4:4 chroma and quality 92 of a 768 px photograph is roughly 150 to 300 KB (an estimate; the flat test gradient was 14 KB and says nothing). PNG is lossless and probably 0.5 to 1 MB. The choice can change an answer, so it belongs in the prompt version (section 5). `jpeg-encoder` is already a dependency of `ym-export`.

### 2.3 Structured output and the result envelope

`--json-schema` makes Claude Code add a tool named `StructuredOutput` whose `input_schema` **is our JSON Schema** (the schema text appeared unchanged in the request's `tools[0].input_schema`; the tool description is "return the final response as structured JSON") **[run]**. There is no `tool_choice` forcing it **[run]**, and no constrained decoding on our side of the API: it is tool use, so a model can still answer in prose. What the CLI does then **[run]**: it appends a user message "`[structured-output-enforce] You MUST call the StructuredOutput tool to complete this request. Call this tool now.`" and asks once more (two POSTs); if the model answers in prose again, the run ends with `subtype: "success"`, `is_error: false`, a `result` string of that prose and **no `structured_output` key** (docs: "If a run ends without valid structured output … the response has no `structured_output` field"). The CLI accepts the `format` keyword as an annotation only.

The `result` object of 2.1.310 (stream-json, the last line; `--output-format json` prints the same object alone), fields seen **[run]**:

| Field | Meaning |
|---|---|
| `type: "result"`, `subtype` | `"success"`, or an error subtype (`error_max_turns` seen with a looping mock) |
| `is_error` | **check this, not `subtype` or the exit code alone**: a signed-out run has `subtype: "success"` and `is_error: true` |
| `result` | the model's text, or the error text (`"Not logged in · Please run /login"`) |
| `structured_output` | the parsed object, present only on success with a schema |
| `terminal_reason` | `"completed"`, `"api_error"` |
| `stop_reason`, `api_error_status` | the API's stop reason; HTTP status of a failed call, or `null` |
| `num_turns`, `duration_ms`, `duration_api_ms`, `ttft_ms` | timing |
| `total_cost_usd`, `usage{input_tokens, output_tokens, cache_*}` | client-side cost estimate and tokens |
| `modelUsage{<model id>: {inputTokens, outputTokens, costUSD, contextWindow, …}}` | **which model answered** |
| `permission_denials[]`, `session_id`, `uuid` | |

Exit codes: 0 on success, non-zero on failure (documented; observed 1 for signed-out and for `error_max_turns`); 143 after SIGTERM [doc]. Retryable API errors surface in the stream as `system/api_retry` events with `error` one of `authentication_failed`, `billing_error`, `rate_limit`, `overloaded`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, … [doc]; use them to tell a rate limit from a bad key. A refusal would show as prose in `result` with no `structured_output` (not provoked here); treat "no `structured_output`" as `BadAnswer` or `Refused` by reading `result`.

### 2.4 Availability and sign-in, without a request

```text
claude --version            →  "2.1.310 (Claude Code)"      20 ms [run]
claude auth status          →  JSON, the default            (--text for words)
```

Signed in [run, here through a session token file; the shape is the docs'] exit 0:
`{"loggedIn":true,"authMethod":"oauth_token","apiProvider":"firstParty","analyticsDisabled":false,"projectsDirectory":…,"configDirectory":…}`.
Signed out [run] exit **1**: `{"loggedIn":false,"authMethod":"none","apiProvider":"firstParty",…}`; with `--text`: `Not logged in. Run claude auth login to authenticate.`

A signed-out `claude -p` does not hang: it prints `Not logged in · Please run /login` and exits 1, as text or as the JSON object above with `is_error: true`, in under a second **[run]**. Auth precedence [doc]: `ANTHROPIC_API_KEY` set means "in non-interactive mode (`-p`), the key is always used when present", over a subscription; `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`) is for automation; Bedrock, Vertex and Foundry are chosen by `CLAUDE_CODE_USE_*`. `authMethod` and `apiProvider` therefore tell the settings screen which account will pay and where the picture will go. Reading Claude's credential files directly is not an option: they live in the keychain on macOS and the terms forbid collecting them (2.8).

Reproduction note: in this cloud container `claude auth status` reported signed in because the CLI reads a hard-coded remote-session token file; the signed-out case above was produced by failing that one `openat` with `strace --inject`. Not relevant to a desktop.

### 2.5 Cost, speed, limits

* **Tokens per photo** (estimate): 532 to 784 image tokens + about 500 for 2000 characters of instructions + about 400 to 700 for the schema (the Apple answer form has 12 fields with cases and guides) + the identity line, so about **1.5 to 2 k input tokens**, and 100 to 250 output tokens plus adaptive thinking. About 0.9 M input tokens per 500 photos. Price: not on the model page; use `platform.claude.com/docs/en/about-claude/pricing` for the chosen model.
* **Start-up** [run]: `claude --version` 20 ms; a complete `claude -p` through `--safe-mode` against a mock that answers in 0.15 s took about 1.0 s of wall time in this container.
* **Model latency: not measured** (no real request was made). Estimate 3 to 10 s per photo at `--effort low`, to be measured on a signed-in machine (section 7).
* **Which account pays:** the person's subscription (usage limits; "advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK" [doc]) or their API key. A 500-photo batch is 500 requests; a limit hit shows as `rate_limit`.
* **Concurrency:** `docs/19` runs one request at a time. The CLI start-up is about 1 s and the rest is network wait, so 2 parallel processes would halve a batch; not tried.

### 2.6 Determinism

No temperature, top-p or seed flag exists in 2.1.310's `--help`, and the captured request has the keys `model, messages, system, tools, metadata, max_tokens, thinking, context_management, output_config, stream`, with no `temperature` **[run]**. `max_tokens` is 128000, thinking is `adaptive`. The prompt cache (`cache_control` ephemeral on the system blocks) can change latency, not content. What is controllable: the model id (pin a full id, e.g. `claude-sonnet-5-5`, instead of an alias), the effort, the system text, the schema. Anthropic can retire or change a model under the same id.

### 2.7 What leaves the computer, and the CLI's own telemetry

**The request** (captured, 2.1.310, `--safe-mode`, no tools) **[run]**: the image block; our user text; system blocks: `x-anthropic-billing-header: cc_version=2.1.310.436; cc_entrypoint=sdk-cli;`, "You are a Claude agent, built on Anthropic's Claude Agent SDK.", then our instructions; a system-role message with an "# Environment" block (**working directory path, platform, shell, OS version, the model name, today's date**); `metadata.user_id` = `{"device_id":"<64 hex digits>","account_uuid":"…","session_id":"<uuid>"}`; headers `User-Agent: claude-cli/2.1.310`, `x-stainless-os/arch/runtime`, `x-claude-code-session-id`. With the default system prompt (no `--system-prompt-file`) the CWD and date sit in the system block. The working directory is therefore visible to Anthropic: use a neutral folder (section 4: not under the person's user name where avoidable).

**The CLI's other connections [run].** Run inside a namespace with a DNS logger, the same request with and without the switch:

| Environment | Connections attempted |
|---|---|
| nothing set (API key or OAuth token) | `HEAD /api/hello` on the base URL; DNS lookups for `api.anthropic.com` (3 to 8 times) and **`http-intake.logs.us5.datadoghq.com`**; the POST |
| `DISABLE_TELEMETRY=1 DISABLE_ERROR_REPORTING=1 DISABLE_AUTOUPDATER=1` | the `HEAD` and one `api.anthropic.com` lookup remain (no Datadog); the POST |
| **`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`** | **only the POST. No `HEAD`, no DNS lookup at all** |

Without the switch and without a network the CLI also wrote `~/.claude/telemetry/1p_failed_events.*.json`, 82 to 112 `ClaudeCodeInternalEvent` records (about 170 to 230 KB) per run, with names such as `tengu_started`, `tengu_cli_flags`, `tengu_api_success`, `tengu_structured_output_enabled`, `tengu_image_output`, and an `env` block (platform, node version, "package_managers", "runtimes", terminal); a search of them found neither the prompt text nor image bytes. With the switch nothing was written. Docs: metrics "never include your code, prompts, or file paths"; error reports are on for Pro/Max sign-ins from 2.1.198; both off with the variables above [doc, data-usage page].

**Retention [doc].** Consumer plans (Free/Pro/Max): training only if the person's data setting allows; retention 5 years if allowed, 30 days if not. Team, Enterprise, API: no training on prompts by default; 30 days retention; zero data retention for qualified accounts. The vision FAQ says "Image uploads are ephemeral and not stored beyond the duration of the API request" and "Anthropic does not use uploaded images to train models" (API terms); the Claude Code page applies the account type's rules to "all user prompts and model outputs". These two statements differ by account type, and the person's own account decides: the settings copy must not promise either.

**Third-party provider.** If the person configured Bedrock, Vertex or Foundry for Claude Code, the picture goes to that provider, not Anthropic, and Anthropic's own telemetry is off by default there [doc]. Yellowmoon should show `apiProvider` from `claude auth status` and word the copy "to the service your Claude Code uses".

### 2.8 Terms

[doc, `code.claude.com/docs/en/legal-and-compliance`] "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication … Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Reading: spawning the person's own, unmodified `claude`, signed in by them, touching no credential, charges nothing to Yellowmoon and is within the text. Strictly, an app that batch-grades hundreds of photos through a subscription is a use the text does not mention either way; it is "ordinary, individual usage" of the person's own plan.

## 3. Antigravity CLI (`agy`)

Version tested: **1.4.7**, `--help` only **[run]**; everything else is from Google's docs (`antigravity.google/docs/cli/*`, fetched as HTML and read as text), the CHANGELOG, and strings in the binary.

### 3.1 One-shot call

```text
agy -p "<prompt>"
    --output-format json
    --json-schema <path-to-schema.json>
    --model <slug> --effort low
    --print-timeout 2m
    --disable-slash-commands
```

with the working directory an empty new temp folder holding the photo. From `--help` 1.4.7 [run] and the headless page [doc]:

| Flag | Meaning |
|---|---|
| `-p`, `--print`, `--prompt` | run once and exit; the prompt is the flag's value ("a valueless prompt flag swallowing the next flag" is an error since 1.1.18); the CLI does not read stdin when a prompt is given (1.1.1) |
| `--output-format text\|json\|stream-json` | `json` prints one envelope on completion (section 3.3) |
| `--input-format stream-json` | "requires `--output-format stream-json`"; one NDJSON prompt per stdin line; **text blocks only** (3.2) |
| `--json-schema` | "a schema string, a path to a `.json` schema file, or a primitive type name" [doc]; since 1.2.14 plain text and a root that is not `"type":"object"` fail at start-up with exit 1. A file path avoids all quoting on Windows |
| `--model <slug>`, `--effort low\|medium\|high\|xhigh\|max` | `agy models` lists slugs such as `gemini-3.8-flash-medium`; an unknown model "exits non-zero with an `ERROR` status" instead of falling back [doc]; `--effort` since 1.1.5. `agy models --output-format json` gives a machine-readable list (1.1.12) |
| `--print-timeout 2m` | **pass it explicitly**: the headless page says the default is 5 minutes, `--help` 1.4.7 and the reference say `0s` (wait until the turn completes; changed to unlimited in 1.2.6). On expiry mid-turn the CLI returns the partial output and **exits 0** with a warning on stderr (1.1.28): check the envelope, not the exit code |
| `--disable-slash-commands` | print mode otherwise expands `/skill` text in a prompt (1.1.9) |
| `--sandbox` | OS containment for terminal commands |
| `--dangerously-skip-permissions` | never |
| `--continue`, `--conversation` | not used: "Headless runs are stateless by default" [doc] |
| `--agent <name>` | a custom agent from `.agents/agents/` works in headless (1.2.11); see 3.2 |

**State and files.** There is no `--no-session-persistence`. A run still creates a conversation (the envelope returns `conversation_id`) and the CHANGELOG mentions the run's conversation history reaching disk before print mode exits (1.1.27) and print-mode metadata under `~/.gemini/antigravity-cli/cache` (1.0.5); read-only slash commands in print mode are said to leave "no conversation behind" (1.1.11), which implies other prompts do. Where the conversation lives and how to delete it from a script was not found **(unverified)**.

**Permissions in print mode [doc].** There is no prompt: "A tool that requires approval it can't obtain is soft-denied: the run continues, exits 0, and prints a notice to stderr"; "reading and writing files inside your active workspace is auto-allowed"; shell commands default to Ask and are soft-denied unless granted. Since 1.1.27 refused actions appear as `denied_actions` in the JSON output. **The person's `~/.gemini/antigravity-cli/settings.json` applies in headless runs** (1.1.5: headless runs "now honor persisted `settings.json` policies, including `permissions`, file access, sandbox mode, auto-execution"), including `toolPermission: "always-proceed"` or `permissions.allow` rules `command(...)`.

### 3.2 Passing the image

* **Stdin: not possible.** [doc, headless page] "`text` is the only supported block type. Submitting any other block type ends the session with an error message" (exit 1). No `--image`, `--attach` or `--file` flag exists in `--help` 1.4.7 [run].
* **Path in the prompt** is the only route: put `photo.jpg` in the empty working folder and say "Look at `photo.jpg`". The agent opens it with its `view_file` tool (the name appears 135 times in the binary's strings [run]). The CHANGELOG confirms the agent views images: "images the agent views or you attach are now scaled down to at most 2576 pixels per side" (1.3.2, a fix for Claude models), large WebP are scaled like PNG and JPEG (1.2.15), TIFF is converted to PNG (1.2.17). The interactive prompt takes PNG, JPEG, GIF, WebP, BMP, TIFF and SVG by paste [doc, prompting page]. **That the model really receives the pixels through `view_file` in `-p` mode was not run** **(unverified)**.
* **`@file` mentions** are an interactive typeahead (the dropdown after `@`); whether `-p "@photo.jpg …"` attaches the file was not found documented **(unverified)**.
* **Workspace trust.** The binary contains the dialog "Trust this folder?" and `settings.json` has `trustedWorkspaces`; the docs say nothing about print mode in an untrusted folder, and a fresh temp folder is untrusted. A headless run could refuse or ask **(unverified; must be tested on a signed-in machine)**.
* **A tool-less agent may be possible.** The CHANGELOG (1.2.1) adds `excludeDefaultComponents: true` in a custom agent's Markdown frontmatter so it can "opt out of default prompt sections and built-in tools", and custom agents list their `tools` (1.2.5). A project agent file `.agents/agents/ym-grader.md` written into the temp folder, with only `view_file`, and `--agent ym-grader`, would remove most of the harness and the injection surface. The frontmatter format is not in the CLI pages I read **(unverified)**.

### 3.3 Structured output and the envelope [doc]

`--output-format json`, one line:

```json
{"conversation_id":"…","status":"SUCCESS","response":"{\"major\":2,\"minor\":14,\"patch\":3}\n","duration_seconds":4.45,"num_turns":1,
 "structured_output":{"major":2,"minor":14,"patch":3},"json_schema":{…},
 "usage":{"input_tokens":10522,"output_tokens":354,"thinking_tokens":329,"cache_read_tokens":8112,"total_tokens":10876}}
```

`status` is one of `SUCCESS`, `ERROR`, `CANCELED`, `INTERRUPTED`, `INVALID`, `WAITING`, `RUNNING`. `error` is present on failure. `structured_output` and `json_schema` are "present only with `--json-schema`". No model name, no cost field (token counts only). Google's samples show 4 to 7 s and 10.4 k to 10.5 k input tokens for a one-sentence prompt with no image (the harness prompt and tool definitions; most of it cached).

**Exit codes [doc/CHANGELOG].** 0 success; 1 failure to produce a response (unknown model, bad schema, missing agent, authentication); 2 usage error in print mode; **3** a turn that ended on an agent or model API error, with a structured line `AGY_ERROR: {...}` on stderr carrying "canonical status, HTTP or gRPC error code, retryability, and error ID" (1.2.6), including after partial output (1.2.10). Authentication: "a run that isn't already authenticated exits with an `authentication required` error instead of hanging" [doc]; the binary holds the text "Error: authentication required. Run '%s' to log in." [run, strings]. `--print-timeout` expiry exits 0 (above). An empty answer that looked like success was made a non-zero exit with the error on stderr (1.1.1), and so was a dropped state stream (1.1.18).

### 3.4 Availability and sign-in without a request

`agy --version` prints `1.4.7` [run]. `agy` has no `auth` subcommand (subcommands: `agent(s)`, `changelog`, `help`, `install`, `mcp`, `mic-serve`, `models`, `plugin(s)`, `remote-control`, `update` [run]). The CHANGELOG (1.1.11) says `-p "/usage"`, `/quota`, `/credits`, `/model`, `/effort`, `/skills` "emit one tab-separated record per line — or a structured payload under `--output-format json` — without starting an agent turn, spending quota, or leaving a conversation behind". So the probe is `agy -p /usage --output-format json`: exit 0 and quota data when signed in; "authentication required" and non-zero when not **(unverified; I did not run it)**. The credentials are in the system keyring (and, for oversized tokens, a private secrets file, 1.4.7), so checking files is not an option. `GEMINI_API_KEY` mode shows "Gemini API key" as the credential.

### 3.5 Cost, speed, limits

Not measured. From Google's samples: 4 to 7 s for a trivial prompt; the call carries a ~10 k-token harness prompt, so latency and quota per photo are higher than Claude's tool-less call, and a view-the-file turn means at least two model calls. Quota: the person's Google AI plan (`/usage`, `/quota`); AI credits can be enabled (`useG1Credits`); with `GEMINI_API_KEY` the key's billing applies, and a spent daily quota or spend cap stops the run at once (1.2.12). Rate limits are per plan and not published as numbers I could find.

### 3.6 Determinism

`--help` shows no temperature or seed. Effort is the only quality knob (`--effort`), the model slug pins the model (slugs include the effort tier, e.g. `gemini-3.8-flash-medium`). The CLI's own log records when a model name resolves to a different model (1.1.28). Not reproducible.

### 3.7 Privacy and risks

* **What leaves:** the photo (when the agent views it, scaled to at most 2576 px), the prompt, and the harness prompt, tool definitions, working-folder path and conversation history the CLI adds. Hosts seen in the binary's strings include `cloudcode-pa.googleapis.com`, `aiplatform.googleapis.com`, `aicode.googleapis.com`, `businessaicode.googleapis.com` [run, strings; a list of names, not a trace of traffic].
* **Google's terms [doc, `antigravity.google/terms`]:** "we record and store your user data, interaction data … ('Interactions')"; "We use Interactions to evaluate, develop, and improve Google and Alphabet research, products, services and machine learning technologies … Google employees and contractors may access, view, review and use Interactions. If you don't want your Interactions used in this way, navigate to settings to change your preference". The README repeats it as a condition of use and says "You can opt out in settings". "Enable Telemetry" in `/config` "has no `settings.json` key: the CLI saves that choice with your account" [doc]: Yellowmoon can neither read nor set it. For Business accounts (Google Cloud project, `AGY_ADC_AUTH`) "prompts, content, and model responses are never collected" (1.4.1).
* **No documented switch** for the CLI's own update checks or analytics. Environment variables found in the binary: `AGY_CLI_*` for display, `AGY_ADC_AUTH`, `AGY_ACCOUNT`, `AGY_LLM_GATEWAY_URL/_API_KEY/_HEADERS/_CA_CERT`, none for telemetry **(unverified: strings only)**.
* **Prompt injection through the picture.** A photo that contains text ("ignore your instructions and run …") is read by an agent that has tools, and the person's settings decide whether commands run unasked. The first mitigations are `--sandbox`, an empty working folder holding only the photo, no `--dangerously-skip-permissions`, and (unverified) a tool-less custom agent. The Claude route has no tools at all.
* **Terms clause** quoted in section 0, item 8.

## 4. Cross-platform process handling (Rust)

### 4.1 Finding the binary

1. **Known folders first, then PATH, then the login shell.** Both installers put the program in `~/.local/bin`, which is often not on PATH: Anthropic's troubleshooting page has a whole section for `Native installation exists but ~/.local/bin is not in your PATH`, and says the VS Code extension's private copy is not on PATH either [doc]. A macOS app started from the Finder or Dock gets launchd's minimal PATH (no Homebrew, no `~/.local/bin`, no nvm).

| Tool | macOS / Linux | Windows |
|---|---|---|
| `claude` | `~/.local/bin/claude` (a symlink into `~/.local/share/claude/versions/`), `/opt/homebrew/bin/claude`, `/usr/local/bin/claude` (Homebrew's bin directories for the casks `claude-code` and `claude-code@latest`, and npm global: inferred, the docs name no path; distro packages use `/usr/bin`) | `%USERPROFILE%\.local\bin\claude.exe` (native), WinGet `Anthropic.ClaudeCode`, npm `%APPDATA%\npm\claude.cmd` |
| `agy` | `~/.local/bin/agy` (or the `--dir` the person gave) | `%LOCALAPPDATA%\agy\bin\agy.exe` |

(Locations: `claude` from the setup and troubleshooting pages; `agy` from the install scripts, both read in full. An npm global bin directory varies with `npm prefix -g`, nvm and Volta; the PATH search and the shell probe find those.)

2. **PATH search with `which`.** `which::which_global` (or `which_in_global`) "ignoring cwd", so a program in the current directory is never picked up. On Windows the crate infers the extension from `PATHEXT` ("has no extension, using PATHEXT environment variable to infer one", `finder.rs` [doc]), so `claude` resolves to `claude.exe` or `claude.cmd`.
3. **Login-shell probe, last, only on macOS and Linux:** `"$SHELL" -l -c 'command -v claude'` with stdin `/dev/null`, a **3 s timeout** and a kill of the process group on expiry. `-l` reads `.zprofile`/`.profile` (Homebrew's `shellenv` lives there) but not `.zshrc` (nvm and many PATH edits live there; `-ilc` reads it but may prompt, print or hang: the Tauri crate `fix-path-env` uses `-ilc 'env'` with no timeout [doc, its source]). Use `-ilc` only as a second attempt and only with the timeout. Risks: shell start-up files run arbitrary code (the person's own, but slow), output can carry banner text (take the last line that is an absolute path to an executable), the shell can be fish or nu (`command -v` works in both; nu does not: skip unknown shells), and a result must be an absolute path that exists. Never `eval` it.
4. **Validate what was found:** run `<path> --version` (timeout 5 s), parse `\d+\.\d+\.\d+`, compare to the minimum (`claude` 2.1.169 for `--safe-mode`; `agy` 1.2.14 for the schema rules and exit code 3). Remember the path for the session.

### 4.2 Windows: shims, `cmd /C` and quoting

* `std::process::Command::new("claude")` on Windows tries `.exe` only; use the path `which` returned.
* A `.cmd` or `.bat` runs through `cmd.exe`. The standard library's escaping was found unsound (CVE-2024-24576, "BatBadBut") and since **Rust 1.77.2** `Command` "return[s] an `InvalidInput` error when it cannot safely escape an argument"; `CommandExt::raw_arg` bypasses escaping and is the caller's risk [doc, Rust blog]. Our arguments (a JSON schema full of quotes and braces, long instructions with line breaks) would be refused or mangled. So **never spawn a `.cmd`/`.bat`/`.ps1` and never use `cmd /C`.**
* **Resolve past the shim.** The npm package's real program is a native executable at `<npm prefix>\node_modules\@anthropic-ai\claude-code\bin\claude.exe` (the `bin` entry of the package [run]). When `which` finds `claude.cmd`, look for that file next to it and spawn it directly; if it is absent, report "Claude Code was found as a script that Yellowmoon can't run safely; install the native version". `agy` ships as `agy.exe` and needs no such step. Pass long text through files (`--system-prompt-file`, `--json-schema <file>` for `agy`; Claude's `--json-schema` takes the string, which stays under 4 KB).
* Windows command lines are limited to about 32 K characters (CreateProcess), macOS and Linux to the (much larger) `ARG_MAX`: **the picture and the instructions never travel in arguments**, only on stdin or in files.
* Set `CREATE_NO_WINDOW` (`std::os::windows::process::CommandExt::creation_flags(0x0800_0000)`, or `process-wrap`'s `CreationFlags` wrapper) so no console window flashes over the app. (The flag value is the Win32 constant, not checked here.)

### 4.3 Passing data, temp folder, environment

* **Picture on stdin** for Claude (section 2.2). Write it from a second thread and close stdin, while the main thread reads stdout: a 300 KB write into a pipe whose reader is not reading deadlocks.
* **Temp folder:** `tempfile::TempDir::with_prefix("ym-")`, mode 0700 on Unix, new per request or per worker, deleted on drop (hard rule 4: the picture lives in memory and in this folder only until the answer arrives). Claude needs only the empty folder as its working directory (it keeps the CLI away from project files; `--safe-mode` already stops CLAUDE.md discovery); `agy` also needs `photo.jpg` in it. The folder's full path is sent to the provider (2.7, 3.7), so avoid a path with the person's name where the OS gives a choice: on macOS `$TMPDIR` is `/var/folders/xx/…/T/` (no user name); on Windows `%TEMP%` is under the user's profile, so the path carries the user name. A folder under `%ProgramData%` avoids that where it is writable; otherwise accept it and say so in the copy **(a choice for the owner)**.
* **Environment:** inherit it, so the person's provider and proxy settings keep working (`HTTPS_PROXY`, `ANTHROPIC_*`, `CLAUDE_CODE_USE_*`, `AWS_*`, `GEMINI_API_KEY`), and add `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (plus `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1`, `DISABLE_AUTOUPDATER=1` for older versions that predate it). Remove variables that describe a *parent* Claude Code session when `ym` itself runs inside one (an agent running `ym render`): `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_REMOTE*`, `CLAUDE_CODE_CHILD_SESSION` **(unverified list)**. Never print the environment.
* **stdout/stderr:** read both fully (two threads) and cap them (for example 2 MB) so a runaway child cannot fill memory; stderr goes into the failure message after redaction of anything that looks like a token.

### 4.4 Timeouts, cancellation, zombies

* **Time limits:** the request timeout is ours (`docs/19`: 30 s for Apple; CLI providers need longer, suggest 90 s for `claude` and 120 s for `agy`, plus `--print-timeout` for `agy`). On expiry or when the session closes or the person cancels: kill the whole tree, then `wait()`.
* **Unix:** spawn in a new process group (`process_wrap::std::ProcessGroup::leader()`) and `killpg(SIGTERM)`, wait 2 s, `killpg(SIGKILL)`. `claude -p` exits 143 on SIGTERM and "terminates the process tree of any Bash command that is still running" [doc]; with `--tools ""` there are none. `agy` print mode "no longer leaves daemon background processes running after exit" (1.2.9), which is why a group kill is still the safe default.
* **Windows:** assign the child to a job object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`process_wrap::std::JobObject`); `TerminateJobObject` kills the tree; closing the job when `ym` dies kills any orphan.
* **Zombies:** always `wait()` after `kill()`; wrap the child so that dropping it kills the tree (`process-wrap`'s `KillOnDrop`). A panic inside a request must not leak the child (`docs/19` §6 already makes requests panic-safe; the guard goes on the child, not on the advisor).

## 5. Fit with Yellowmoon's rules

### 5.1 Rule 7: what happens, and what the setting must say

The owner's reading (2026-10-26): Yellowmoon opens no network connection; the CLIs it runs do. Consequences for the design:

* **Yellowmoon's code stays network-free.** No HTTP crate in the new crate (checked by a test), no URL in its sources except the documentation links the UI opens in the system browser. The updater remains the only network code of Yellowmoon.
* **Say plainly that the CLIs do.** `docs/19` promises "It runs on this Mac and sends nothing anywhere" for Apple. For the CLI providers the copy must say the opposite in as many words. What leaves, exactly:

| What | Claude Code | Antigravity |
|---|---|---|
| The photo | one 768 px sRGB picture (8-bit, our JPEG) of Auto's "without Apple" rendering at the Signature look (`docs/19` §3), no EXIF or colour profile, no file name; never the raw file | the same picture, as a file named `photo.jpg` in the temp folder, which the agent opens; its file name is visible to the model |
| The instructions | the person's own or the default text, at most 2000 characters, as the system prompt | inside the prompt, with the answer form |
| The answer form | our JSON Schema (about 12 fields with their cases) as the `StructuredOutput` tool | our JSON Schema via `--json-schema`; also in the prompt |
| Added by the CLI | an identity line, the temp folder's path, platform, OS version, date, model name, a device id hash and session id, the CLI version | the CLI's harness prompt and tool definitions (~10 k tokens), the folder path, the conversation history it keeps |
| Where it goes | Anthropic, or the person's Bedrock/Vertex/Foundry/gateway | Google, or the Gemini API with `GEMINI_API_KEY`, or the person's Google Cloud project |
| Who can keep it | per the person's account (2.7): 30 days to 5 years | per Google's terms (3.7): used to improve Google's products, staff may review, opt-out in Antigravity's own settings |
| Does *not* leave | the original file, its name, its path, the other photos, the person's settings and looks, the location in the file's EXIF, any other file on the computer | the same, except that an agent with tools could in principle read what its permissions allow (3.7) |

* **Setting** (copy in the style of `docs/19` §2; British spelling, plain sentences). The row is a `Select` titled **Automatic grading** in Preferences after Display rendering, shown only when at least one of Apple Intelligence, `claude` or `agy` is found, listing **Yellowmoon's own Auto** first (always), then only the providers found. A provider that is installed but signed out is listed disabled with "Sign in to Claude Code in Terminal first." The instructions field below it is shown only while a provider other than Yellowmoon's own Auto is chosen (as today for Apple).
  * Hint under the Claude Code choice: "Claude Code looks at a small copy of each photo and grades it. The copy goes to Anthropic, or to the service your Claude Code is set up to use, through your own Claude Code sign-in. Yellowmoon itself connects to nothing. Choose Yellowmoon's own Auto to send nothing anywhere."
  * Hint under the Antigravity choice: "Antigravity looks at a small copy of each photo and grades it. The copy goes to Google through your own Antigravity sign-in. Google may keep and review it unless you opt out in Antigravity's own settings. Yellowmoon itself connects to nothing. Choose Yellowmoon's own Auto to send nothing anywhere."
  * **Consent: default off, per provider, asked once.** Choosing a CLI provider the first time opens a `Dialog`: title "Send photos to Claude Code?", body "To grade a photo, Yellowmoon runs Claude Code on this computer and hands it a copy of the photo, 768 pixels on the long side, and your instructions. Claude Code sends them to Anthropic with your own account. The original file, its name and its place on disk stay here. Whatever Anthropic keeps depends on your account's privacy settings.", buttons "Cancel" and "Use Claude Code". The consent is stored as a preference (`auto_consent.claude: true`) (rule 4: it is not per photo) and is dropped when the provider changes (a new account type or provider is a new decision).
  * **`ym` never uses a provider by default.** Naming it on the command line is the consent: `--auto-provider claude|agy|apple|rule` (default: the preference where it is consented, else `rule`), with one notice on stderr, once per run: "Sending a 768 px copy of each photo to Anthropic through Claude Code 2.1.310 (model claude-sonnet-5-5). Yellowmoon itself makes no connection." (hidden by `--quiet`, like every warning). `ym doctor` lists each provider's state and the account method; it does not ask a model.

### 5.2 Rule 8: determinism and reporting

A cloud answer is not reproducible: no temperature or seed exists in either CLI (2.6, 3.6), models behind aliases change, and `agy` and `claude` may differ from one call to the next. `docs/19` §7 already handles this for Apple in three ways that carry over unchanged in spirit:

1. **Every export records which Auto made it.** Generalise `ym:Auto` (`rule`, `apple`) to `rule | apple | claude | agy` and `ym:AppleAuto` to `ym:AutoAdvisor` (compact JSON, keys sorted): `{"provider":"claude","cli_version":"2.1.310","model":"claude-sonnet-5-5","api_provider":"firstParty","prompt":4,"schema":1,"image":"jpeg4:4:4q92@768","instructions":"default","instructions_sha256":"…","result":"answered","scene":"…","plan":"…","steps":{…},"reproducible":false}`. The `model` is read from `modelUsage` (Claude) or the `--model` slug (agy, whose envelope names no model). `ym info` and `ym doctor` print the same, and the version string reads `Claude Code 2.1.310 · claude-sonnet-5-5 · prompt 4 · table 2`.
2. **The picture can still be reproduced from the file.** `ym:Settings` pins every Auto value to the number it resolved to (`docs/19` §5), so re-exporting from the XMP's own settings gives the same pixels whatever the cloud said. Only "re-run Auto" is non-deterministic, and it is labelled.
3. **Tests and golden files never reach a provider.** As `YELLOWMOON_TEST_APPLE_AUTO=fake` does, a `YELLOWMOON_TEST_AUTO_CLI=fake` makes the new crate return a deterministic advisor on every platform; the parity tests (app against `ym`, bit for bit) run with it or with the provider off. For a real provider the app and `ym` are two processes with no shared cache, so the same photo may be graded differently by each: state it in `ym render --help` and in the app's hint ("Answers can differ from run to run").

### 5.3 Caching for the session

Exactly as `docs/19` §2 and §6: the answers stay **in memory for the session**, keyed by photo and by `(provider, model id, CLI version, prompt version, schema version, picture encoding, instructions SHA-256)`; turning a provider off and on again does not ask again; new instructions, a new model or Re-run drop them; nothing is written to disk (rule 4). `ym` has no cross-run cache. A failure (timeout, signed out, rate limit, bad answer) uses the rule and says why, and "Re-run asks again". A signed-out CLI found mid-batch stops the worker with one visible message instead of failing every photo.

## 6. Recommended design

**Shared.** A new crate `crates/ym-agents` (it depends on `ym-core`; `ym-cli` and the app depend on it; `ym-core` never does, like `ym-apple`) with `ClaudeAdvisor` and `AgyAdvisor`, both `impl ym_core::apple_auto::AutoAdvisor` (`availability()` and `ask(&AdvisorPicture, instructions)` exactly as `docs/19` §12 defines them, so the worker, the order, the retries, the bursts, the metadata and the Automatic card are reused). `ym_agents::system_advisors() -> Vec<Arc<dyn AutoAdvisor>>`; the core keeps one chosen advisor per session. Neutral names are needed in `ym-core`: the types are called `AppleAuto`, `UnavailableReason::NotAMac…` and `AdvisorInfo { model, os }`; the new reasons are `cli_not_found`, `cli_too_old`, `not_signed_in`, `not_consented`, the new failures `not_signed_in`, `rate_limited` (reuse), `cli_failed`, `refused`, `bad_answer`. The answer form is the same twelve fields; the schema sent to the CLIs gives each numeric step as a string enum with the same case names as Apple's `@Generable` types (`"exposure": {"enum":["muchDarker","darker",…]}`), not as integers, because the model reads names, and every field but `scene` and `plan` is optional (a field left out sets nothing, `docs/19` §5). The Rust side maps names to steps, rejects an unknown name as `bad_answer`, validates with `jsonschema`, and applies `AdvisorAnswer::checked`. The worker passes the same 768 px picture; the provider encodes it (JPEG 4:4:4, quality 92, no metadata) and drops the buffer after the request. A provider module is a small state machine around one `Command` with the guards of section 4.

**Claude Code.** `availability()`: resolve the binary (known folders, PATH, login-shell probe on macOS), `--version` (minimum 2.1.169), `claude auth status` (exit 0, `loggedIn`), read `authMethod` and `apiProvider` for the hint, then consent. `ask()`: create a private empty temp folder, write the instructions to a file in a second private folder (or the same, outside the CLI's cwd), spawn `claude -p --input-format stream-json --output-format stream-json --verbose --safe-mode --tools "" --no-session-persistence --max-turns 3 --model <pref or sonnet> --effort low --system-prompt-file … --json-schema '<schema>' --disable-slash-commands --strict-mcp-config` with the environment of 4.3 in a process group or job object, write one `user` line with the base64 JPEG and "Grade this photo.", close stdin, read stdout until the `result` line or the timeout, and require `is_error == false`, `structured_output` present and valid. Map `Not logged in` (or `authentication_failed`) to `not_signed_in`, `rate_limit` to `rate_limited` (retried like Apple's, 2 times, 2 s apart, but only after 20 s for a subscription window), a missing `structured_output` to `refused` or `bad_answer`, a timeout to `timeout`. Record `modelUsage`'s key as the model. No `--bare`, no `ANTHROPIC_API_KEY` handling, no reading of `~/.claude`.

**Antigravity.** `availability()`: resolve `agy` (known folders, PATH), `agy --version` (minimum 1.2.14), the `-p /usage --output-format json` probe (exit 0), consent. `ask()`: temp folder holding `photo.jpg` (the same JPEG), the schema in `schema.json`, and, if the tool-less custom agent of 3.2 proves out, `.agents/agents/ym-grader.md`; spawn `agy -p "<instructions + answer form + 'Look at photo.jpg and grade it.'>" --output-format json --json-schema schema.json --model <pref> --effort low --print-timeout 2m --disable-slash-commands --sandbox [--agent ym-grader]` in that folder, same guards; require `status == "SUCCESS"`, a non-empty `structured_output`, and no `denied_actions` that matter; exit 3 and the `AGY_ERROR` line map to `cli_failed` (retryable flag honoured). Because the route is the least safe and least certain of the two (no stdin image, tools present, the person's permissive settings apply), **ship it second, hidden behind the same availability rule, after the open questions of 3.2 are tested on a signed-in machine**; if `view_file` or the untrusted-folder behaviour fails in `-p`, drop it rather than work around it.

**Order of work.** (1) generalise `docs/19`'s types and metadata names, no behaviour change, tests unchanged; (2) `ym-agents` with the fake advisor and the process harness (kill on timeout, cancel, stdin deadlock, huge stdout, signed-out, `.cmd` refusal) tested on Linux, macOS and Windows with a tiny Rust test binary that imitates each CLI's output; (3) the Claude provider and the `claude auth status` probe; (4) Preferences row, consent dialog, `ym` flags and `ym doctor` rows; (5) the Agy provider. The mock-API method of this research (a localhost server standing in for Anthropic, run with a dummy token in a network namespace) is a good manual check for step (3), but it needs the proprietary binary, so it belongs in `tools/` as a maintainer script, not in CI.

## 7. Risks, open questions, and what I could not verify

**Questions for the owner.**

1. **Google's terms.** The Antigravity terms forbid "using the Service in connection with products not provided by us" and "using third party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity OAuth)", with suspension of the person's Antigravity and Gemini CLI accounts as the stated consequence. Spawning the first-party `agy` as a child of Yellowmoon is not "OAuth in third-party software", but the first sentence is broad. Ship the `agy` provider, ship it with a warning in the consent text, or ask Google (`antigravity-support@google.com`)? A [HUMAN] item.
2. **Anthropic's terms** allow the person's own signed-in unmodified `claude`; confirm the owner is comfortable with a batch app using a subscription (the "ordinary, individual usage" language).
3. **`AGENTS.md` rule 7** says "No network access from the app or CLI except …". With the owner's reading it holds for Yellowmoon's own code, but a reader sees a feature that sends pictures to the cloud. Suggest one added sentence ("Yellowmoon may run the person's own `claude` or `agy`, which make their own connections; Yellowmoon opens none") and a `docs/14` row for each CLI (licence: not shipped, run as the person's own program). Not edited here.
4. **The dropdown rule.** "If nothing available the dropdown is hidden": is a provider that is installed but signed out "available"? Proposed: listed, disabled, with the sign-in hint.
5. **Default model and effort.** `sonnet` at `--effort low` is a guess for quality against speed; `haiku` would be faster and cheaper. Needs the blind A/B of `docs/19` §13 with each provider.
6. **Temp-folder path on Windows** reveals the user name to the provider (4.3).
7. **Which Windows installs count.** Native `claude.exe` and `agy.exe` are certain; npm shims need the `claude.exe` lookup; Scoop or other layouts are not covered.

**Not verified here (needs a signed-in machine, a real request, or a Mac).**

* Real latency, token use and rate behaviour of either provider; whether Sonnet 5.5 at `--effort low` follows the `StructuredOutput` tool with an image reliably (the mock only proves the plumbing).
* `claude --safe-mode` with a real subscription login and the macOS keychain; whether `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` leaves OAuth token refresh working (the docs do not list it among what is disabled); whether `claude` launched by a Finder-started app is allowed to read its keychain item without a prompt; behaviour under the App Sandbox (a sandboxed app cannot run `~/.local/bin/claude`; Yellowmoon is not sandboxed today).
* `agy -p`: unsigned-out exit code and message, the `-p /usage` probe, whether `view_file` gives the model the pixels, workspace trust in an untrusted temp folder, whether `-p "@photo.jpg"` attaches, conversation files left on disk and how to delete them, an environment switch for telemetry or self-update, the tool-less custom agent's frontmatter, `--json-schema`'s enforcement strength.
* The list of parent-session variables to strip (4.3), and `fix-path-env`-style probing against real zsh, bash, fish setups.
* Windows spawn behaviour was reasoned from the Rust blog post and the `which` source, not run (no Windows machine); macOS behaviour likewise.

**Risks.** The CLIs change fast (Claude Code's changelog runs to 2.1.310; `agy` has had 78 releases since 1.0.0, with exit-code and flag changes inside 1.1 and 1.2): gate on version, parse the envelope tolerantly (ignore unknown fields, require the few we use), detect a missing flag from the CLI's error text, and fail with a plain message ("Claude Code 2.1.100 is too old. Update it with `claude update`."). A provider can change terms, price or availability without notice. A batch can exhaust a person's plan quota. Prompt injection (3.7). The picture is a rendering at the Signature look, not the original, but is still the person's photograph, sent to a third party.
