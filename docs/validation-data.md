# Validation data

This file names, for every gate in `docs/13-testing.md`, the public dataset, generated dataset or independent tool that checks it, with its licence, the script that fetches it, where it may be stored and whether the build sandbox can reach it. V1 takes no measurements of its own and needs no test shoot (`AGENTS.md`, V1 data rule), so nothing here needs a camera. The few [HUMAN] items left are reviews, emails and Mac-only runs, listed at the end.

## Where data may live

| Class | Meaning | What goes in |
|---|---|---|
| **REPO** | committed to git | only our own generated vectors and fixtures (small, reproducible by a script in the repo), and shipped data with its licence file. Never raw files, never ARRI files, never third-party datasets |
| **CI cache** | `testdata/`, git-ignored, restored by `actions/cache` keyed on the manifest hash; tier 2 files may also sit in a public test bucket with their attribution (`docs/test-photo-sources.md`) | CC0, CC BY and CC BY-SA files, and permissively licensed code |
| **CI fetch** | downloaded from the original host on each run, not cached, not mirrored | research-use and evaluation-only sets (Kodak, McMaster, Gharbi, NUS-8) |
| **LOCAL** | on a development machine only; never committed, uploaded, cached or fed to CI | copyrighted files (golden tier 3), HdM curves, Adobe DNG Converter output files, anything whose terms forbid copying; the **local-eval** tier below (real files of unclear licence) |

### The local-eval tier

Next to the CC0 corpus and the golden tiers sits **local-eval**: nine real Sony ARW files for looking at real photographs on a development machine (`tools/fetch/real-eval.sh`, `tools/fetch/README.md`). They come from three public GitHub repositories, each at a pinned commit and each file at a pinned git blob id (the table is `SOURCES` in `tools/fetch/real_eval.py`); plain `git` reaches all of them (224.6 MB).

NonCommercial and ShareAlike: not redistributable by this project |

- **Redistribution:** none of them clearly allows it. The immich repository comes closest (a public-domain statement by its maintainers), but a claim with no provenance, next to an AGPL `LICENSE`, is not a licence this project can rely on. It could move to a CI tier if the origin of the two files is confirmed (for example the same body and mode exists as a CC0 file on RawDB or raw.pixls.us, or the contributor confirms); the maintainer decides, and nothing adds it to CI.
- **Class:** LOCAL, `testdata/real/` (git-ignored). Never committed, never in CI (the script exits with code 2 when `CI` or `GITHUB_ACTIONS` is `true`), never uploaded, cached or redistributed, and no picture made from them goes into the repository (golden references, screenshots, bug-report attachments).
- **Use:** decoder and pipeline smoke tests that skip without them (`crates/ym-core/tests/real_files.rs`, `render_real.rs`, `export_real.rs`, `tools/dngfit/tests/real_files.rs`, `training/illum/smoke_real.py`), the auto-exposure study (`tools/eval`) and visual checks. **No gate depends on them**; results are reported as "local, not corpus data" and do not close a corpus gate.
- **Names:** the link names are the ones the local tests read. The two immich files carry the raw variant in the name (`ILCE-6300_craw.ARW`, `ILCE-7M2_unc14.ARW`), the others the model from the file's own Model tag.

### The white-scale photos (Play Raw)

The white scales of the stand-in bodies (`docs/03`, *White scale of stand-in bodies*) are fitted on the white-balance presets that real files carry. Three sets feed them: the owner's A1 photos (`tools/fetch/owner-photos.sh`), the local-eval files above, and **17 Play Raw files** of discuss.pixls.us that `tools/fetch/white-scale-photos.sh` fetches into `testdata/white-scale/play-raw/` (`tools/fetch/white-scale-photos.json` pins name, size, SHA-256, download address, post, poster and licence of each).

- **Licence:** the posts state "Creative Commons, By-Attribution, Share-Alike" (the Play Raw template, no version number) or, for one file, "Public Domain". Files whose post states no licence, or a NonCommercial one, are not in the table.
- **Class:** CI cache would be allowed for CC BY-SA files (`docs/test-photo-sources.md`, tier 2), but nothing here is a gate or runs in CI: the fit is run by hand (`python3 -m training.white_scale.fit --check`) and its tests skip without the files. The files are never committed, shipped or redistributed; the scales take only the numbers the camera wrote (`docs/14` rule 8).
- **Reach:** `discuss.pixls.us` and its file store (`pixls-discuss.s3.dualstack.us-east-1.amazonaws.com`) answered from the sandbox on 2026-10-24; two files were downloaded and matched their SHA-256.

## Synthetic ARW files and independent decoders

The ARW corpus (RawDB, raw.pixls.us) and the CC0 golden tiers cannot be fetched from the sandbox, so the golden set and the decoder, detection, metadata and pipeline tests use **synthetic ARW files** and independent decoders as the oracle.

- **Writer:** the test-only synthetic ARW writer in `ym-raw` (cargo feature `testgen`, `crates/ym-raw/src/testgen.rs`). It writes ARW containers from known pixel values with uncompressed, cRAW and LJPEG (lossless L) encoders; the container carries the TIFF/IFD layout, Sony maker note (model ID, ISO) and the SR2 block (black, white, white balance), and the writer covers the embedded preview, lens tags and lossless M/S. Seeds are fixed, so files are reproducible and nothing needs storing.
- **Scenes:** the generated synthetic ARW set (`tools/fetch/synthetic.sh`, `training/synth`, `tools/golden synth`): physically based scenes (rawtoaces reflectances in a chart with gradients, a neutral ramp, fine detail, a blown highlight and a deep shadow, under eight lights and one mixed light, through the published curves of six bodies, with a known Poisson-Gaussian noise model and four CFA phases) written as every ARW variant on every body, each with a JSON sidecar of ground truth (the true light and white, the noise model, per patch the ALEXA-estimate reference and the "Sony through ARRI matrix" baseline, a made-up embedded JPEG). About 37 mosaics and 61 ARW files, under 300 MB, a few minutes, no download; `--full` adds a 6240 × 4160 scene for timing and an evaluation scene with the CIE CES (CC BY-SA, `testdata/` only). The files are **synthetic only**, and the golden tier built from them stands in for the CC0 tier (`docs/13` section Golden images).
- **Oracles:** LibRaw through `rawpy` (PyPI, LibRaw 0.22.1, reads every variant except ARW 6.0; Lossless L only for the ILCE-1, ILCE-7x and ILCE-9x models, and Lossless M/S only with its compression tag rewritten from 7 to 6, which `tools/oracle/rawpy_compare.py` does on a copy) and `rawler` (`tools/oracle`, test-only, LGPL, never linked into a shipped crate). ExifTool (`libimage-exiftool-perl` from apt) reads the same files as a third, independent reader, and its Sony tag tables (`Sony.pm` on `raw.githubusercontent.com`) are the reference for model IDs. ARW 6.0 needs LibRaw master (built from source, `git clone https://github.com/LibRaw/LibRaw`) and lightcraft.
- **Real files, locally:** `tools/fetch/real-eval.sh` fetches the nine local-eval files so the decoder, the colour chain and the export can be looked at on real photographs. They are not corpus data and prove nothing for a gate.
- **What this proves:** that our writer and our decoder agree with decoders written by other people, so a container, encryption or bit-packing misreading shared by writer and decoder shows up as an oracle mismatch. Values are compared exactly (cRAW within the dither rule in `docs/04`).
- **What it cannot prove:** behaviour of real cameras: firmware quirks, ARW 5.x maker-note offset shifts, real lossless M/S data, real lens-tag values, real noise and real tone curves. Anything measured only on synthetic files is reported as "synthetic only", and the gate stays open until the corpus run passes.
- **Closing the gap:** on a machine that can reach the hosts, `tools/fetch/samples.sh --refresh` fills `tools/fetch/manifest.json` (it ships with an empty file list and the body list), the result is committed, and `samples.sh` then downloads and verifies the corpus in CI. No other change is needed.
