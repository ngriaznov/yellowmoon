# Validation data plan (M0-10)

V1 takes no measurements of its own and needs no test shoot (`AGENTS.md`, V1 data rule). Every gate in `docs/13-testing.md` is therefore checked against a public dataset, a generated dataset or an independent tool. This file names that source for each gate, its licence, the script that fetches it, where it may be stored, and whether the agent environment that wrote this plan can reach it. **Nothing here needs Mykyta's camera.** The few [HUMAN] items left are reviews, emails and Mac-only runs, listed at the end.

Reachability was probed on 2026-10-12 with `curl` from the agent container. Re-probe before relying on a row; the proxy policy changes.

## Where data may live

| Class | Meaning | What goes in |
|---|---|---|
| **REPO** | committed to git | only our own generated vectors and fixtures (small, reproducible by a script in the repo), and shipped data with its licence file. Never raw files, never ARRI files, never third-party datasets |
| **CI cache** | `testdata/`, git-ignored, restored by `actions/cache` keyed on the manifest hash; tier 2 files may also sit in a public test bucket with their attribution (`docs/test-photo-sources.md`) | CC0, CC BY and CC BY-SA files, and permissively licensed code |
| **CI fetch** | downloaded from the original host on each run, not cached, not mirrored | research-use and evaluation-only sets (Kodak, McMaster, Gharbi, NUS-8) |
| **LOCAL** | on a development machine only; never committed, uploaded, cached or fed to CI | copyrighted files (golden tier 3), HdM curves, Adobe DNG Converter output files, anything whose terms forbid copying |

## Stop-gap while the corpus hosts are unreachable: synthetic ARW files plus independent decoders

The ARW corpus (RawDB, raw.pixls.us) and the golden set cannot be fetched from here, so no real Sony file exists in this environment. Decoder, detection, metadata and pipeline work proceeds on **synthetic ARW files** and uses independent decoders as the oracle:

- **Writer:** the test-only synthetic ARW writer in `ym-raw` (cargo feature `testgen`, `crates/ym-raw/src/testgen.rs`). It writes ARW containers from known pixel values with uncompressed, cRAW and LJPEG (lossless L) encoders; the container carries the TIFF/IFD layout, Sony maker note (model ID, ISO) and the SR2 block (black, white, white balance), and the writer grows with the decoders (embedded preview, lens tags, lossless M/S). Seeds are fixed, so files are reproducible and nothing needs storing.
- **Scenes:** the generated synthetic ARW set (`tools/fetch/synthetic.sh`, `training/synth`, `tools/golden synth`): physically based scenes (rawtoaces reflectances in a chart with gradients, a neutral ramp, fine detail, a blown highlight and a deep shadow, under eight lights and one mixed light, through the published curves of six bodies, with a known Poisson-Gaussian noise model and four CFA phases) written as every ARW variant on every body, each with a JSON sidecar of ground truth (the true light and white, the noise model, per patch the ALEXA-estimate reference and the "Sony through ARRI matrix" baseline, a made-up embedded JPEG). About 37 mosaics and 61 ARW files, under 300 MB, a few minutes, no download; `--full` adds a 6240 x 4160 scene for timing and an evaluation scene with the CIE CES (CC BY-SA, `testdata/` only). The files are **synthetic only** and the golden tier built from them is a stop-gap until the CC0 tier is fetchable (`docs/13` section Golden images).
- **Oracles:** LibRaw through `rawpy` (PyPI, LibRaw 0.22.1, reads every variant except ARW 6.0; Lossless L only for the ILCE-1, ILCE-7x and ILCE-9x models, and Lossless M/S only with its compression tag rewritten from 7 to 6, which `tools/oracle/rawpy_compare.py` does on a copy) and `rawler` (`tools/oracle`, test-only, LGPL, never linked into a shipped crate). ExifTool (`libimage-exiftool-perl` from apt) reads the same files as a third, independent reader, and its Sony tag tables (`Sony.pm` on `raw.githubusercontent.com`) are the reference for model IDs. ARW 6.0 needs LibRaw master (build from source, `git clone https://github.com/LibRaw/LibRaw`) and lightcraft.
- **What this proves:** that our writer and our decoder agree with decoders written by other people, so a container, encryption or bit-packing misreading shared by writer and decoder would show up as an oracle mismatch. Values are compared exactly (cRAW within the dither rule in `docs/04`).
- **What it cannot prove:** behaviour of real cameras: firmware quirks, ARW 5.x maker-note offset shifts, real lossless M/S data, real lens-tag values, real noise and real tone curves. Anything measured only on synthetic files is reported as "synthetic only" in `docs/STATUS.md`, and the gate stays open until the corpus run passes.
- **Closing the gap:** on a machine that can reach the hosts, `tools/fetch/samples.sh --refresh` fills `tools/fetch/manifest.json` (it ships with an empty file list and the body list), the result is committed, and `samples.sh` then downloads and verifies the corpus in CI. No other change is needed.
