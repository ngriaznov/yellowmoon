# 11 · User interface

Reference: `design/mockups/` (open `index.html`; the pages run offline), `design/screenshots/` (every state at 2880×1800), `design/tokens.css` / `tokens.json`. The mockups are the source of truth for layout, copy and states. This spec covers behaviour, data wiring and anything the mockups don't show.

Style: "bold grid, white". Figtree throughout. 3 px black rules divide the window into cells. Each tool tab has a flat colour that fills its tab, its title block, its slider fills and any changed value box. Controls are square and boxed (2 px borders). The photo fills its cell edge to edge. Yellow (#FFC20E) is the brand colour: the moon mark, the start screen, the Look tab, progress fills.

## Window

- Tauri window, `titleBarStyle: Overlay`, hidden title. The traffic lights sit over the folder cell; keep 84 px of left padding there.
- Minimum size 1180 × 760. Default 1440 × 900.
- Light appearance only in V1 (the dark variant in `research` is not shipped).

### Component library notes (M3-01)

The components live in `src/components/` and are exported from `src/components/index.ts`. `components.html` (run `npm run dev`, open `/components.html`) shows every component in every state; `/components.html?replica=photos&tab=light` (also `start`, `export`, `wizard`) rebuilds a mockup screen from them, and `e2e/components.spec.ts` compares each with the mockup pixel by pixel. Decisions taken where the mockups and the table above differ or are silent:

- **Tab bar:** the separators are 3 px, as in `photos.html` (the table said 2 px).
- **Wheel:** 92 px across including the 2 px border, 88 px inside it (the table's 88). The puck travels inside the rim, so a point of length 1 sits 7 px in.
- **AUTO in a card header** is a 26 px toggle button (`AutoToggle`: ink while automatic, pressing it restores Auto); the AUTO and EDITED tags on the Automatic rows are the 22 px `Tag`.
- **Tags** the mockups do not draw: ON takes the tab colour, REDUCED the peach error colour, `done` is ink like READY, `active` (a running file's "45%") is yellow like DEVELOPING. A `sm` size (14 px) exists for the CAN'T OPEN tag on a 60 × 40 thumbnail.
- **Slider patches:** `onChange(value, final)`. While the thumb is dragged it fires at most once per animation frame with `final = false`, then once with `final = true` on release; keys, typed values, Reset and double click fire once with `final = true`. The same contract holds for `Wheel` and `CurvePlot`. A control keeps showing its own value until the controlled value catches up (or one second passes), so a slow reply never makes the thumb jump back.
- **Reset** on an automatic value (Exposure, Kelvin, Tint, Sharpen, Noise reduction) must go back to Auto, not to the number Auto resolves to: pass `onReset`.
- **Wheel keys:** arrows nudge the puck (Shift ×10), Home, Delete or Backspace centre it; exposed as a slider whose value is the strength, with the strength and hue in `aria-valuetext`.
- **Curve:** a press adds a point on the curve at that x, a drag moves it, dragging an inner point more than 14 px off the plot deletes it. The two end points move up and down only and cannot be deleted. They are drawn only while the plot is hovered, focused or the point is selected, so a resting plot looks like the mockup. Keys: Tab through the points, arrows move one code value (Shift ×10), Delete removes, Return on the plot adds a point in the widest gap. Input and Output show the dragged point, else the position under the pointer, else the selected point, else the middle.
- **Focus:** every interactive element gets the global 3 px ring with a 2 px offset, including tabs and segments (the focused cell is lifted so its neighbours do not paint over the ring). The slider draws its own ring because its native input is transparent.
- **Photo cell:** `PhotoCell` carries `data-viewport` and reports `{ x, y, width, height, scale }` through `onRect` on mount, on ResizeObserver callbacks and on window resize. With `native` (default inside Tauri) it draws no `<img>` and is transparent; otherwise the photo is an `<img>` letterboxed on paper.
- **Base line height** is `normal`, as in the mockups (the skeleton's 1.4 made every row a few pixels taller).
- **Added beyond the table** because the mockups use them everywhere: `Button`, `LinkButton`, `KeyHint`, `ProgressBar`, `TitleBlock`, `Field`, `Rows`, `InfoRow`, `AutoRow`, `SwitchRow`, `SearchField`, `Histogram`, `DevelopList`, `WheelGroup`, and the hooks `useTabShortcuts` (⌘1–⌘6), `useWindowDrop` (whole-window drops, with Tauri's real paths inside the app), `useFrameEmitter` and `usePointerDrag`.

### Screen notes (M3-05 to M3-08)

Start, Photos, the six tabs, Crop and Pick white are built in `src/screens/`, on a store (`src/state/store.ts`) that mirrors the core and is the only code that calls `Api`. Decisions taken where this spec or the mockups were silent:

- **Store.** Plain TypeScript with `subscribe`, tested without React; `context.tsx` provides it. Events (`photo_progress`, `thumbnail_ready`, `render_stats`) are applied in batches of about two frames, so 500 photos developing do not draw 2000 times. A status event that arrives before the session snapshot (the core emits while `open_paths` is still answering) is kept and applied when the session arrives.
- **Patches.** `store.update(patch, final)` sends one patch at a time per photo. While one is in flight, later drag patches fold into one waiting patch, so a slow core is never flooded and the last value always arrives. Fields that need no resolving (look, contrast, light preset, wheels, curve, switches, crop, …) show at once; Auto fields wait for the core's reply. A failed patch shows the error and asks the core for the settings again.
- **Auto semantics.** A value equal to what Automatic resolves to *is* Automatic: typing +0.30 into Exposure, or dropping the slider on its detent, sends `{ exposure: { kind: "auto" } }` (the same for Kelvin/Tint together, Sharpening and Noise reduction). Reset on a row of an Auto field sets only that value (and collapses to Auto when it matches); the card's Reset and the AUTO button send Auto. The AUTO button of the Exposure card says whether *exposure* is automatic, not Contrast or Brightness. White balance counts as automatic only when `white_balance` is Auto, `light_source` is Auto and no white was picked.
- **Light presets.** `light_source` is sent as it is; while White balance is Auto the core resolves a kelvin for the preset (the mock: Day 5500, Shade 7500, Tung. 3200, LED 4800, Fluor. 4100) and the Kelvin box shows it as a change.
- **Undo and redo** are per photo, in memory, 100 steps. An entry holds only the fields one change touched (before and after, as two patches), so changes made by "Apply to" on other photos never get in the way. A whole drag, or a whole crop session, is one step. ⌘Z waits for patches in flight. "Re-run" is a step.
- **Apply to.** The Look card's scope is a mode, as in the mockup (default All): a tile click or the end of an Intensity drag sends `update_settings` for the current photo, then `apply_look(scope, look, intensity)` for This/Picked/All. Other photos' cached settings are dropped and asked for again when shown. Reset on the card picks the default look at 100 % the same way. "Make default" appears beside Reset when the selected look is not the default.
- **Look tab.** Tiles are numbered in display order (built in, ARRI, your LUTs); keys 1–9 pick them, also while the search box has a filter. Thumbnails are requested through `look_thumbnail` when a tile scrolls into view and again 250 ms after the photo's other settings stop changing. A missing look is a disabled tile with the note "File missing or changed. Import again." With no ARRI looks the group shows "The free ARRI Look Library is not imported yet." and "Import ARRI looks →".
- **Crop.** While the panel is open the core is told only the angle and the orientation, with the frame set to the whole photo, so the viewport keeps showing the whole straightened photo and the webview draws the frame; Done sends the frame with the angle and the orientation as one change; Cancel (Esc) puts the old crop and orientation back. Return finishes, except on a focused button, which it presses. ←/→ do nothing while cropping; a click on another photo ends the crop without keeping it. A frame that is the whole photo at 0° is sent as `crop: null`. Aspect presets follow the shape of the frame (4:5 on a landscape frame is 5:4). Handles move with the arrow keys (Shift ×10); the frame moves too.
- **Pick white.** A click sends `white_pick: [x, y]` (the whole photo's coordinates, 0–1) through `update_settings`, ends the mode and shows the Colour tab, whose White balance card then carries an EDITED tag until Reset. The core must set the white balance from the pick (the mock sets it to Manual); the UI shows EDITED for any `white_pick` that is not null. From the keyboard the layer takes focus, the arrows move a crosshair and Return picks. Only the picture counts: a click on the paper around a letterboxed photo is ignored.
- **Header.** The status text is `render_stats`. "Fit 24%" is the cell's device width over the photo's width (the mockup's 34% is made up). The zoom menu offers Fit, 50 %, 100 % and 200 %; Z toggles Fit and 100 %; ⌘+/⌘− step through the four. A double click on the photo sends `viewport_input toggle_zoom`; with ⌘ or Ctrl the wheel zooms, and at zoom levels above Fit the wheel and a drag pan.
- **Browser build.** `PhotoCell` draws the mock's picture (`fixtures/grade.ts`: the mockup's flat-shape grading, with orientation, straighten and crop); in the app the native layer draws and the cell is transparent.
- **Export cell and panel.** See "Screen notes (M3-09, M3-11, M3-13)" below. ⌘, opens Preferences, and ⌘W asks first while an export is running.
- **IPC additions** (not in `docs/01`): `close_session()`; `histogram(photo_id)` → `{ red, green, blue }` bins; `look_thumbnail(photo_id, look_id)` → PNG bytes; `CameraInfo.model` ("ILCE-1") for the RAW tab's "Detected" row.
- **Errors** from any command show in a black bar at the foot of the window until dismissed.

### Screen notes (M3-09, M3-11, M3-13)

The wizard, the Export panel, Preferences and About are built in `src/screens/` (`ImportLooks.tsx` with `wizard/`, `export/`, `dialogs/`) on pure rules in `src/wizard/model.ts`, `src/export/*.ts` and `src/state/menu.ts`, all tested without a screen. `e2e/export.spec.ts` and `e2e/wizard.spec.ts` compare every mocked state with `design/screenshots/` (0.00 to 0.55 % of the pixels differ by more than 24 on a channel after the fidelity pass below; `export-dng.png` is the exception at 2.2 %, see Export › DNG below). Decisions where this spec or the mockups were silent:

**Wizard**
- **Steps and locking.** The reducer (`reduceWizard`) holds the five steps. A step ahead of the current one is locked (`aria-disabled` in the rail); a finished one can be revisited from the rail or Back; Next is `aria-disabled` with the reason in its `title` and in the footer line. Choose needs a package; Get the files needs a file for each chosen package (the files are *judged* on Recognise, so a wrong file still lets the person see why); Recognise needs every chosen package matched and every `.cube` question answered; Import waits for the copy. Cancel and Back are disabled while files are copied (there is no cancel in `looks_import`). The import starts from the Import button, never from an effect.
- **Recognition** runs as each file arrives (`looks_recognise`) and again when Recognise is entered, so a file that went away is reported as Missing. Rows: MATCH (a chosen package); NOT CHOSEN (another package: "This is Look Library · LogC3, not Look Library · LogC4, which you chose. Download … or go back and choose this one."); QUESTION then READY (`.cube` files that match no package; the generic question has three answers, LogC4, LogC3, LogC3 · Rec.709, and starts from what the names suggest); CAN'T USE (the recogniser's reason, for example the ALF4-only sentence of `docs/08`); MISSING. Files that are not imported stay listed with a Remove link. The mockup's peach note stays under the table.
- **Downloads watcher.** The "Watch my Downloads folder" switch is the preference `watch_downloads_during_import` (also in Preferences). While Get the files is on screen and the switch is on, `looks_watch_downloads(true)` runs and `download_found` events add the zip; leaving the step stops it. If macOS refuses, the answer carries `problem`, which is shown in plain words, and the switch goes back off. Drops (whole window, step 2 only) and "Choose file…" (`choose_look_files`, zips and `.cube` files) work at any time on that step.
- **Finish.** Tiles are the first seven imported looks on the current photo through `look_thumbnail` (plain boxes when no photo is open), then "And N more". Default look offers Neutral, Signature and the first imported look (the full list is the Look tab's job). Display rendering appears only when display LUTs were imported now; "ARRI's" means the LogC4 Rec.709 gamma 2.4 LUT (`preferredDisplayLut`). Downloaded zip (Keep it / Move to Trash, default Trash) is offered for zips only and uses `trash_path`. Done applies the three choices, then returns to where the wizard was opened.
- **Looks › Import .cube….** A small dialog (`CubeImport`) with the same question; ARRI packages chosen here are imported without asking. Also offered as "Import .cube…" under the Look tab's grid.
- **Copy.** The mockup's "For this mock, it is already here." is dropped. New lines say what is wrong and what to do ("Look Library · LogC4 is missing. Go back and add it.").

**Export**
- **State.** Options, scope and the running export live in the store, not in the panel. Options start from `preferences.export_defaults` and every change is saved back as the default (a drag saves on release; a template that can't be used is never saved). Scope starts as Picked when anything is picked, else This photo, each time the panel opens with no run. "All" counts photos that can be exported (not those that failed to develop).
- **Estimate and command.** `export_estimate` and `cli_preview` are asked again (150 ms after the last change) whenever the job changes. The footer reads "Export N photos" with "≈ 75 MB · ⌘↩" (≈ 1.0 GB from 1000 MB; the time estimate is the button's tooltip). The estimate also carries `adjusted_photos` ("N photos have adjustments this command doesn't include.") and `dng_unavailable`.
- **DNG.** The option is disabled with the aria label "DNG, not available for this look" and the note "This look includes its own display rendering, so it can't go into a DNG. Pick another look or export TIFF."; if DNG is already chosen the same note replaces the DNG note and the Export button is held back. The DNG note gets a second paragraph with the Adobe notice and the line that later white balance changes in other apps are approximate (`docs/09` §Legal and §What other apps show): this adds three lines to the DNG state, the one place the screen differs visibly from `export-dng.png` (2.2 % of pixels).
- **Colour space notes.** sRGB: "Best for sharing and the web." (mockup). Display P3: "Wider colours. Use it for recent Macs, iPhones and iPads." Rec.2020: "Very wide colours, for video and HDR work."
- **Size.** "Full · 8640 px" is the longest side of the biggest photo in the job; Long edge is a slider from 1000 px to that size in 20 px steps, starting at 3000 px, and remembers its last value. Long edge is disabled for photos hardly bigger than 1000 px.
- **Save to.** "Choose…" calls `choose_folder`; "Use default" (shown once a folder was chosen) puts the session's `<source folder> export` back. **File name** is a real text box (`{name}_{look}`), with the first file name previewed under it and an explanation under it when the template can't be used (`templateProblem`: empty, `/ \ :`, a leading dot, an unknown or unclosed `{token}`, more than 200 characters); with several photos and neither `{name}` nor `{seq}` the panel warns that every photo would get the same name.
- **Queue.** One row per file: WAITING, a percentage on yellow, DONE, SKIPPED (orange: the file existed and "If it exists" is Skip) or FAILED with the reason. The core's `export_progress` names the file under way and the files finished; a failed or skipped file is reported once, as it finishes. Row names start as the panel's prediction and take the core's name as each file is reached (Keep both adds " 2"). The title is Exporting, Exported or Not exported (nothing could be saved); the blurb says "1 of 3 done." or "3 photos saved to Lisbon export." plus what failed or was skipped. Cancel asks the core to stop and returns to the options with "Export stopped. N photos were saved."
- **Browsing.** Closing the panel does not stop the export. The header's Export cell reads "Exporting 1 of 3" with a yellow strip along its foot, then "Exported" until Done; clicking it reopens the queue. While the panel is open the cell keeps its plain name, as in the mockup. The update cell is held back while a run is going (tooltip "Restarts after the export finishes"). ⌘W during a run asks "An export is running" (Keep exporting / Stop export and close); closing stops the run.

### Fidelity pass (M3-15)

A second look at every mocked state, with tools rather than eyes alone. Method: each mockup page is rendered in the state of its screenshot (`window.__inst.setState`, see `design/README.md`) and reproduces `design/screenshots/*.png` exactly for 23 of the 24 states (the 24th, `photos-look-teal.png`, was captured with the panel scrolled by 357 px, 3 px short of its 360 px of travel; the first e2e used 356 and measured 1.5 %). Then the app and the mockup were compared box by box and text by text: `e2e/helpers/domDump.ts` lists every visible element with its own text, border or background (position, size, font size, weight, tracking, colour), `compareScreen` writes that list when `YM_DOM_DUMP=1`, and a 1 px shift, a wrong weight or a missing word shows up where a screenshot threshold lets it through. The same comparison at 1180 × 760, 1280 × 800, 1512 × 982, 1920 × 1080 and 2560 × 1440 (the mockup's `min-height: 760px` and photo-cell formula must hold at every size) found one layout difference, fixed below. Captures, reports and dumps go to `node_modules/.cache/yellowmoon-e2e/` (Playwright empties `test-results/` at the start of every run).

Fixed:
- **Start:** "Change" and "Import →" are 15 px like their row, not 14 px (start screenshots 0.06 % → 0.00 %).
- **Wizard:** the Recommended and Match tags are 26 px tall (the mockup sizes them content-box: `Tag size="lg"`); the peach note under the recognition table is 686 px wide and the Finish step's segmented groups 484 px (also content-box in the mockup); the tick in finished rail steps matches the mockup's glyph (26 × 20 px).
- **Export:** the photo chip has no tabular numbers on this screen, as in the mockup; the header's Export cell shows no progress strip while the panel is open (the queue is on screen); the mock's TIFF command names `--compression` only when it is not the default (LZW), as the mockup's does.
- **Photos:** the look group count reads "2 of 7", not "2 OF 7"; the Curve tab starts with the inner point nearest the middle selected (drawn filled with the readout naming it), as in the mockup; at 1180 px the header buttons wrap their labels like the mockup's instead of letting the status text run under the update cell.
- **Crop:** a handle on a frame edge that sits on the edge of the photo cell is drawn just inside it, not half cut off.
- **Header:** a long folder name ends in an ellipsis on one line (full name as tooltip) instead of wrapping to four lines and out of the 75 px cell. The mockup has no rule for it; real folder names are long.
- **Export queue:** truncated file names carry a tooltip.
- **Store:** a look that the current photo could not take (a failed `update_settings`) is no longer sent to the other photos by `apply_look`.

Differences kept on purpose (each is a line in `BUDGETS` of `e2e/helpers/compare.ts` or below the 0.35 % default):
- "Fit 24 %" where the mockup says 34 %: the label is the cell's width in device pixels over the photo's, 2080 / 8640; the mockup's number is made up and does not match its own "Full · 8640 px".
- The photo and the thumbnails are SVG and PNG pictures, the mockup's CSS shapes: anti-aliased edges differ, about 0.1 % of the pixels on every Photos state.
- Light tab: the histogram and the pixel readout come from the photo (a flat-colour mock photo has three peaks); the mockup's are made-up numbers (1.3 %).
- Curve tab: a histogram behind the plot (this document asks for it, the mockup omits it); the spline is the C11 Fritsch–Carlson curve, not the mockup's hand-drawn Bézier, so the ends differ.
- Look tab: "Make default" appears beside Reset when the selected look is not the default (`docs/08` asks for it on the selected tile) and "Import .cube…" sits beside "Import ARRI looks →". Only the teal state shows either.
- Colour tab: the wheel puck travels inside the rim (a unit vector sits 7 px in), so a puck can sit 0.6 to 0.8 px from the mockup's.
- Export › DNG: Adobe's notice and the white-balance caveat (`docs/09` §Legal), 2.2 %. Export › running: the update cell is greyed while an export runs, as `docs/11` says it is disabled (the mockup draws it normal).
- Wizard: the real file name and size where the mockup says "Look Library zip · 181 MB" (a name and a size on two lines); step 2 waits for the zip, so Next is disabled and the footer line has no "For this mock, it is already here."; Cancel and Back are greyed while files are copied.

Numbers after the pass (share of pixels that differ by more than 24 on a channel, 1440 × 900 at 2×): start 0.00 %, Photos tabs 0.12 to 0.15 % (Light 1.31 %, Curve 0.31 %), look-teal 0.24 %, look-search 0.39 %, Export 0.10 % (DNG 2.19 %, running 0.14 %), wizard 0.00 to 0.55 % (step 2, for the Next button).

Tests and tolerance: `toHaveScreenshot` tolerates 0.35 % of the pixels by Playwright's own count (anti-aliasing costs at most 0.25 %), with a budget per state where the difference is on purpose; the old 2 % let a moved line of text through. Every wait is on a condition (all photos developed before "Open photos →", every visible look tile loaded, the filmstrip's thumbnails replaced, the export held with `mockExportHold` and released with `flush()`), not on time. `e2e/global-setup.ts` loads both pages once so the first test does not pay for the dev server's cold start. Limits are 60 s a test and 10 s an `expect`, for a busy machine.

Accessibility (a preview of M4-04): `e2e/a11y.spec.ts` walks the accessibility tree of Start, every tab, Crop, Pick white, the zoom menu, the Export panel in each format and while it runs, the wizard, Preferences and About, and fails on any button, slider, tab, switch, radio, text box, radio group, tab list or dialog without a name; each screen has one `main` (the photo cell on Photos, the drop area on Start, the wizard's main) and one `banner`, and Photos has the folder name as its `h1`. The keyboard alone gets from Start through Open files, Open photos, the tab bar (←/→), a slider (arrows, Shift, Home, ⌘Z), ⌘E and the Export button to Done; a segmented group, a switch, the search box, the look tiles, a typed value (Return, Esc), the wizard and a dialog (focus trapped, Esc, focus returns) work without the mouse; every stop of the Tab order of Start and of the Look tab has the 3 px ring. `axe-core` 4.10 found nothing but the missing `main` and `h1` (fixed) on all of these screens, contrast included. The tab cell's ring now has a 2 px paper gap, so the ring stays on a bounded edge over a title block of the same colour (the RAW tab's blue is the ring's blue). Contrast (`src/styles/contrast.node.test.ts`): text on every tab colour is 6.3:1 or better (Look 13.0, Light 9.0, Colour 12.6, Detail 12.2, Curve 6.7, RAW 6.3), muted text on paper 5.3:1, the focus ring on paper 6.3:1, on ink 3.3:1, on the brand yellow 3.9:1. Where the ring crosses a coloured title block it can fall under 3:1 (Light 2.7, Curve 2.0, RAW 1.0): the paper gap is the answer, and nothing inside a title block is interactive. Safari before 15.4 has no `:focus-visible` and drops a rule whose selector list contains it: `global.css` gives those the ring on `:focus`; Safari before 16.2 has no `color-mix()`, so the wheel, the curve grid and the histogram use the same colours as `rgba()`.

Large folders: the mock takes `?mockPhotos=500` (the twelve fixtures repeat as DSC04213 and on) and `?mockFolder=Name`. In the production build (`vite build`, Chromium, the dev server's React is two to three times slower) a 500-photo folder developing in the background costs one 78 ms task for 2500 events, and a key pressed meanwhile is on screen two frames later in 5 to 72 ms (median 16): the < 100 ms of M3-03 holds for the web view; the native side is Mac work. The filmstrip draws every photo (500 buttons is fine); ⌘A picks the photos that are ready, one `set_picked` each.

## Copy rules

Short, plain sentences that say what happens. British spelling. No exclamation marks. Errors say what went wrong and what to do. Name ARRI and Sony only factually ("Imports ARRI Look Library files"). Never call the output "ARRI" or "ALEXA" footage; say "cinema colour" or "ALEXA-style colour" only in help text, never in the product name.

## Frontend structure

```
src/
  main.tsx, App.tsx              screen routing (Start, Photos, ImportLooks), menus → actions
  api.ts / api.mock.ts           typed Tauri commands (generated types) and a browser mock with fixture data
  updater.ts                     copied from plugout (phases idle/available/downloading/ready/error)
  state/                         React context + reducers: session, current photo settings, export job, looks
  screens/Start, Photos, ExportPanel, CropPanel, ImportLooks, Preferences
  components/                    see table
  styles/tokens.css              from design/tokens.css; fonts/ with Figtree woff2 + OFL.txt
```

No UI framework and no CSS framework. State lives in Rust; the frontend keeps a mirror for rendering and sends patches. Slider drags send throttled patches (one per animation frame) and a final patch on release.
