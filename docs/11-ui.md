# 11 · User interface

Reference: `design/mockups/` (open `index.html`; the pages run offline), `design/screenshots/` (every state at 2880×1800), `design/tokens.css` / `tokens.json`. The mockups are the source of truth for layout, copy and states. This spec covers behaviour, data wiring and anything the mockups don't show.

Style: "bold grid, white". Figtree throughout. 3 px black rules divide the window into cells. Each tool tab has a flat colour that fills its tab, its title block, its slider fills and any changed value box. Controls are square and boxed (2 px borders). The photo fills its cell edge to edge. Yellow (#FFC20E) is the brand colour: the moon mark, the start screen, the Look tab, progress fills.

## Window

- Tauri window, `titleBarStyle: Overlay`, hidden title. The traffic lights sit over the folder cell; keep 84 px of left padding there.
- Minimum size 1180 × 760. Default 1440 × 900.
- Light appearance only in V1 (the dark variant in `research` is not shipped).

### Start

- Header: moon + "Yellowmoon", sub-line "DROP ARW FILES TO START"; "Open files ⌘O", "Open folder ⇧⌘O"; update cell; Export (disabled).
- Left (yellow): "Drop Sony ARW files." and the blurb; a table: Camera "Any Sony camera · every kind of ARW"; Default look (with "Change"); ARRI looks ("Not imported yet" + "Import →", or "87 looks imported").
- Right: dashed drop zone "Drop files or a folder", "ARW only, as many as you like", buttons "Open files…" and "Open folder…". The whole window accepts drops.
- After a drop: the drop zone becomes "Developing N photos" with a progress bar and a list of files, each tagged Waiting, Developing (yellow, "Decoding and demosaicing"), Ready (black, "Auto exposure, white balance and noise") or Skipped (orange #FF5A1F, with the reason, for files that can't be developed). The summary reads "Everything is developed and ready to export." or "N file(s) skipped. Everything else is developed and ready to export." When all are done: "N photos ready" with "Open photos →" and "Start over". "Open photos →" is available as soon as the first photo is ready; the rest keep developing in the background.
- Footer: three steps (Open / Adjust, if you want / Export); the current step is black.
- Non-ARW files in a drop are ignored and not listed; if a drop contains only non-ARW files, the drop zone says "No ARW files in what you dropped."

### Photos

Grid: columns `minmax(0, 1fr) 400px`; rows `75px auto minmax(124px, 1fr)`.

**Header cells**, left to right:

1. Folder cell (300 px): moon, folder name (24 px, 800), "2026-10-04 · 12 PHOTOS" (capture date of the first photo · count).
2. Actions: **Before** (toggles before/after; `\`), **Crop** (C), **Pick white** (W), **Fit 34% ▾** (zoom menu: Fit, 50%, 100%, 200%; Z toggles Fit/100%). Right-aligned status text: "Neural · 42 ms · Display P3" (demosaic path · last render time · output space).
3. Update cell: hidden while idle. "Update available" → "Downloading 42%" → green square "Update ready" (click restarts; disabled while exporting, tooltip "Restarts after the export finishes") → "Update failed" (reason on hover). States come from `updater.ts` as in plugout.
4. Export cell: "Export ⌘E", or "Export N" when N > 1 photos are picked.

**Photo cell:** always exactly 3:2, `width: min(100%, calc((max(100vh, 760px) − 199px) · 1.5))`, centred, no grey surround and no hairlines above or below it. The native wgpu layer draws here (`docs/01` §Native viewport). Portrait and cropped photos are letterboxed with `--paper`. Overlays:

- bottom-left chip, black: look and intensity ("NEUTRAL · 100%"); hidden in Before mode;
- bottom-right, white text with a soft shadow: "Sony A1 · DSC04204 · ISO 400 · 1/125 · f/2.8";
- Before mode: the yellow "Before" button is active and the photo shows the LogC4 signal before look and display transform, labelled "Before · camera log";
- pixel readout while hovering with ⌥ held: "R 182 G 164 B 140" (display values).

**Filmstrip** (bottom left): thumbnails 60 × 40 with 2 px borders; the current one 90 × 60 with a 4 px border; a yellow corner square marks picked photos; failed files show a black tag "CAN'T OPEN". Click selects; ⌘-click or P toggles pick; ←/→ move; horizontal scroll with trackpad. Counter cell: "4 / 12" and "3 PICKED".

**Tool panel** (right, 400 px): six tabs, then the active tab's title block (tab colour, 40 px title, blurb), then cards.

| Tab | Colour | Cards |
|---|---|---|
| Look | #FFC20E | **Automatic** (rows Exposure / White balance / Noise / Camera, each with value, AUTO or EDITED tag and → to its tab; "Re-run") · **Look** (Intensity slider; Apply to: This photo / Picked · N / All · N; search; look grid; "Reset") |
| Light | #0DB7E8 | **Exposure** (AUTO tag; Exposure, Contrast, Brightness) · **High dynamic range** (Highlights, Shadows, White, Black) |

Tab blurbs (from the mockup): Look "Every photo is developed automatically. Pick a look and how strongly to apply it." · Light "Exposure is set for each photo automatically. Adjust it from there." · Colour "White balance comes from the light in the scene. Set it by hand when you want a different mood." · Detail "Sharpening and noise reduction, tuned for each ISO of your camera." · Curve "Fine contrast, for all channels or one at a time." · RAW "How the sensor data is decoded before any colour is applied."

(body name substituted). When `SensorFamily`: "The <body> shares its sensor with the <profile body>, so it uses that profile." When Lossless M/S: add the REDUCED tag and the note from `docs/04`.

### Export (panel)

Replaces the tool panel; black title block "Export" with "N photos from <folder>. Nothing is saved besides the files you export." Rows: Photos (This photo / Picked · N / All · N), Format (JPEG / TIFF / PNG / DNG) with format-specific sub-rows (Quality; Bit depth, Compression; Bit depth; the DNG note), Colour space (sRGB / Display P3 / Rec.2020; "Best for sharing and the web." under sRGB), Size (Full · 8640 px / Long edge + slider), Save to (folder + "Change"), File name (template box `{name}_{look}`), If it exists (Skip / Replace / Keep both), the CLI preview with Copy, the size estimate. Footer: "Export N photos" primary button (56 px, black) and "Cancel". The filmstrip dims photos that won't be exported.

Running: title "Exporting", "1 of 3 done.", progress bar (yellow fill), per-file list (Waiting / n% / Done), note "Originals are never changed. You can keep working while this runs; an update waits until the export is finished." Finished: title "Exported", "3 photos saved to Lisbon export.", note "Originals are never changed. Open the folder or go back to your photos.", buttons "Show in Finder" and "Done".

### Import ARRI looks (wizard)

Full window. Left rail (360 px) with five steps: Choose ("Pick the ARRI packages you want."), Get the files, Recognise ("We check what each package is."), Import ("Copy the looks into the app."), Finish ("Pick a default and clean up."). The current step is yellow, finished steps show a tick, future steps are locked. Main area per step as in the mockup; footer (96 px) with Back / Next and contextual text ("Next unlocks when the zip arrives."). Behaviour: `docs/08-looks.md`.

### Crop (not mocked)

Replaces the tool panel with a black title block "Crop". Rows: Aspect (Original / 1:1 / 4:5 / 16:9 / Free), Straighten slider −45…45° with detent at 0 (`crop.angle_deg`), "Rotate 90°" button (`orientation`), "Reset". Footer: "Done" (Return) and "Cancel" (Esc). The viewport shows the whole photo with the crop rectangle (2 px ink border with a 2 px paper outer stroke), corner and edge handles (10 × 10 squares), and thirds lines while dragging. Crop is per photo and in memory only.

### Pick white

The cursor becomes a crosshair and the header shows "Click something neutral: grey or white." Click samples (`docs/02` C1); Esc cancels. The Colour tab then shows the result with the EDITED tag.

### Preferences (⌘,, not mocked)

A small window in the same style, one column of rows: Default look (dropdown), Display rendering (Ours · ACES 2 / ARRI's, if imported), Export defaults (opens the Export panel's options without photos), Remove location from exports (switch), Watch Downloads during import (switch), Check for updates automatically (switch, default on), Command-line tool (status + "Install…").

## Copy rules

Short, plain sentences that say what happens. British spelling. No exclamation marks. Errors say what went wrong and what to do. Name ARRI and Sony only factually ("Imports ARRI Look Library files"). Never call the output "ARRI" or "ALEXA" footage; say "cinema colour" or "ALEXA-style colour" only in help text, never in the product name.

## Frontend structure

```
src/
  main.tsx, App.tsx              screen routing (Start, Photos, ImportLooks), menus → actions
  api.ts / api.mock.ts           typed Tauri commands (generated types) and a browser mock with fixture data
  updater.ts                     copied from plugout (phases idle/available/downloading/ready/error)
  state/                         React context + reducers: session, current photo settings, export job, looks
  screens/Start, Photos, ExportPanel, CropPanel, ImportLooks, Preferences
  components/                    see table
  styles/tokens.css              from design/tokens.css; fonts/ with Figtree woff2 + OFL.txt
```

No UI framework and no CSS framework. State lives in Rust; the frontend keeps a mirror for rendering and sends patches. Slider drags send throttled patches (one per animation frame) and a final patch on release.

## Tests

- Vitest + Testing Library for components (keyboard, ARIA, reset behaviour).
- Playwright against `api.mock.ts` (no Tauri): the flows Start → drop → Photos → change look → Export → finished; the wizard happy path; error states (unsupported file, missing look). Screenshot comparisons against `design/screenshots/` at 1440 × 900 with a tolerance, for the states the mockups cover.
- M0-06 spike: manual checklist on real hardware for the native viewport (resize, fullscreen, Spaces, display change between P3 and sRGB monitors).
